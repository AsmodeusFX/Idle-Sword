# 修行星图 · 节点清单（ID → 功能）

> 状态：**由三张表生成的交接清单**，不是数据源。内容取自 `Talent.csv`（名称 / 效果 / 价目）、
> `TalentLayout.csv`（位置 / 前置 / 可读名）、`TalentPlan.csv`（意图），因此**改表之后要重新生成**，
> 别手改这里。用途：让新会话（人或 AI）一眼读懂整棵修行树。

**怎么读**：`位置` 是 `(列, 行)`。**列号只决定画在哪**：可以是负的，也**不再要求前置在左边**——
2026-10-06 起"只能向右延伸"那条限制放开了（前置可以指向右边的节点），只保留"**不能成环**"。
**根就是唯一那个没有前置的节点**，行列都不受限，也**不要求在最左一列**。

**`可读名` 一栏**是策划在编辑器里随手起的叫法（`TalentLayout.csv` 的 `label`，**游戏不读**）；
没填就显示 `id`。它与 `Talent.csv` 的 `name`（**给玩家看的**正式名字）是两回事，别混。
`id` 是稳定标识：**存档与配置引用它，永远不能改**；新节点由编辑器自动分配 `t_100001` 起。

**前置语义：任意一条点亮即可**（OR），条数不限。

## 要留意的

- 🚨 **起点 `sdfsdf` 是占位节点（`effect=none`），它买不了** —— 而它后面的节点全都要求
  "任一条前置点亮"，于是**整张星图只剩它一个节点、还点不动，游戏直接卡死**。
  它的两个兄弟（`124124124`、`13124`）同样是占位。这三个是**测试用的临时节点**，用户说会删掉；
  在删掉之前，**游戏里的修行页是点不开的**（编辑器保存时会提醒这一条）。
- **配 `*_system` 这类开关类效果时，`effect_per_level` 必须大于 0**，否则"买了不生效且不报错"
  （加载期现在会直接拒绝这一条）。目前 `realm_system` / `forge_system` 各有一个节点承载。
- **两个灵核门之间的那一段灵石节点，就是这一关的数值投放预算**。灵核只由 BOSS 首杀产出，
  所以"点得出下一个灵核门"等价于"打得过下一只 BOSS"。
