# 初版美术规范

- `idle-sword/Assets/visuals.json`：表现 ID 到资源路径的唯一映射。怪物/剑灵 CSV 只引用表现 ID。
  - **ID 写错现在会报错**：`BattleView._Ready` 会遍历怪物表与剑灵表，核对每个 `visual` 是否在映射里；缺失就写进 `LoadError`，冒烟测试因此直接失败（此前是静默少画一只怪）。
- `Assets/Sprites/`：像素风 SVG 素材，64×64 画布、透明背景、正向姿态。
  - **可编辑真源是 `tools/SpriteGen/Sprites.cs` 与 `Monsters.cs`**，不是这些 SVG。精灵用「字符网格 + 调色板」定义（`.` 为透明，每行可短于 32 格），**按 32×32 设计、每格渲染成 2×2**，产出 64×64 的 SVG。
    - 选 32×32 的原因：主角在 136px 下显示，64 格等于 2.1px/格（糊），32 格等于 4.25px/格，才是粗颗粒像素风的读法。
  - 命令与 SoundGen 同形：`dotnet run --project tools/SpriteGen -- idle-sword/Assets/Sprites [--verify]`。生成后**必须**跑一次 `godot --headless --path idle-sword --import`。产物与 `.import` 边车都入库。
  - `--verify` 会逐字节比对磁盘文件（抓到"有人手改了 SVG"）、校验 rect 合法且 `fill` 属于该精灵调色板、**占用图每格恰好被画一次**，并把文件展开回网格与定义逐格比对。**不要手改 SVG**，改了会被 `--verify` 拦下。
- **全族约定**（让主角、怪物、剑灵读成一套美术）：
  - 统一描边色 `#101823`，比压暗后的背景更暗，保证在暗背景上依然读得出轮廓。
  - 统一眼型：深色眼块 + 一格浅色高光；嘴与眼沿用旧素材取值，换皮后仍认得出是同一只怪。
  - 怪物共用**一张底模**（`Monsters.BlobGrid`），只换调色板与头顶配件（`HornOverlay` / `BowOverlay`）；剑灵与召唤物用无脚的 `WispGrid`（它们飘在半空）。
  - 填充比旧素材整体提亮一档：描边压在暗背景上、填充又暗的话，轮廓会消失在暗角里。
  - `*_flash`：受击白闪用的伴生图，与本体**逐格同轮廓**、所有不透明格填纯白。之所以要一张真图而不是靠 `modulate`：项目跑在 gl_compatibility（LDR）下，顶点色乘不过 1，深色像素提不亮。
- 可以换成相同 64×64 透明 PNG，只需改映射路径；底部中心为锚点，逻辑射程与生命值不依赖图片大小。
- 人物显示尺寸 136，普通怪 96，精英 125，BOSS 194，裂隙 174，剑灵约 70，单位均为 1920 设计坐标。
- 最近邻采样；任意窗口比例时不保证像素整数倍，16:9 画面比例始终保持。
- 当前只有静态姿态。**表现层的动效都在代码里**（`BattleView`）：
  - 待机呼吸 / 移动时的挤压拉伸：`Sprite()` 的 `sx`/`sy` 参数，**绕底部中心缩放**——中心 x 与底边不动，所以世界坐标与命中判定完全不受影响。
  - 迈步扬尘（`TrackPlayerJuice` + `DrawPuffs`）、受击白闪（叠 `player_flash`）。
  - 英雄自身的逻辑位置 `Battle.PlayerX` 与命中判定**不参与**任何动效计算。
  - 后续要换成帧动画时，统一 `idle`、`walk`、`attack`、`hit`、`death`；使用独立 SpriteFrames 资源维护帧率和循环，不将帧参数嵌入战斗代码。
- 背景由独立 BattleView 表现代码绘制**两层**山景与林木（原先三层，压暗时减掉一层——少一层就少一条亮边），没有复用参考游戏美术。
  - 背景配色刻意比实体暗一大截、并加四边暗角：旧配色（天空 `#253f50`、山 `#2f5060`）与旧主角的青绿几乎同色相同明度，两边互相糊在一起，这才是"画面不好看"的真正原因。
  - 暗角与背景都**画在实体之前**，只压背景，不压角色与怪物。
- 中文界面使用系统字体 Microsoft YaHei，备用 Noto Sans CJK SC；未复制或分发系统字体文件。发行前再选定可随游戏分发的字体资源。
  - 系统字体缺失时**不会报错**，界面直接变成豆腐块，只能靠看图发现。打包脚本每次会在 `artifacts/pack-preview.png` 留一张成品实拍截图，作为发行前的人工检查关卡；目标机器缺字体时按上文替换为可随包分发的字体资源。
- **可编辑原稿的分工**：本批像素精灵的真源是 `tools/SpriteGen/` 里的字符网格（见上），改图就改那里再重跑，`art_source/` 留给将来**手绘**的原稿。运行导出物放 `Assets/`，素材来源和授权说明随资源记录。
- 这批素材是**评估性质的当前方案，不是最终美术**：目的是先看「土豆天尊」这个方向在画面上吸不吸引人。角色造型为原创（发芽的椭圆土豆 + 背上的仙剑），只借鉴《土豆兄弟》的**风格取向**（粗颗粒、深描边、高对比、魔性可爱），不照搬其具体形象。

## 音频（同属资源替换规范）

- `idle-sword/Assets/audio.json`：音频 ID 到资源路径的唯一映射，形式与 `visuals.json` 一致。**替换音频只改这个文件**，不需要动代码。
- `Assets/Audio/`：当前是 `tools/SoundGen/` 程序化合成的 8bit 占位素材，16bit PCM 单声道 22050Hz WAV。
- 换成同格式 WAV 即可直接替换；换 ogg/mp3 只需改映射路径。若换用压缩格式，`Audio.cs` 里的循环参数设置会跳过（样本数无法按字节数推算），需要在导入器里设好循环点。
- 导入设置统一 `compress/mode=0`（16bit PCM）。该枚举在 Godot 4.7 里与旧文档不一致，实测 `0`=PCM 16bit、`1`=IMA-ADPCM(4bit)、`2`=QOA；新导入的 WAV 默认走有损压缩，会削掉方波的硬边，需要手动改回。
- 音效按**法术 kind**（projectile/target/ground/buff/summon）分 5 种释放音，不按具体法术或元素区分；BGM 目前只有一首通用战斗曲。
- 这些是让设计可辨识、可验证的占位素材，**不是最终音频设计**；后续正式配乐与音效设计可整体替换。
