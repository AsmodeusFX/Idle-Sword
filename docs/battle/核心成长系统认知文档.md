## 1. 一句话总纲

> **修行决定"你走到了哪里"，法术决定"你会什么"，神通决定"你怎么打"，神识决定"你怎么自动打"。**

四条线各回答一个**互不重叠**的玩家问题，因此各有一个核心系统。四个系统职责必须明确区分，
**不许互相吞并、也不许重复造系统**。

| 系统 | 核心问题 | 主要产出 | 一句话定位 |
| --- | --- | --- | --- |
| **修行** | "我现在修炼到了什么程度？" | 境界、基础属性、系统解锁 | **长期成长主线** |
| **法术** | "我会什么法术？" | 法术库、法术等级、战斗手段 | **战斗内容库** |
| **神通** | "我如何构筑自己的战斗体系？" | BD 机制、条件、规则改变 | **BD 主系统** |
| **神识** | "我能同时处理多少事，以及战斗有多聪明？" | 控制力、自动化、执行逻辑 | **自动化与执行逻辑** |

核心关系（**修行不是所有系统的上级技能树**——它只负责"解锁与阶段"，解锁之后各系统独立运行）：

```text
                    修行（解锁与阶段）
                          │
              ┌───────────┼───────────┐
              ↓           ↓           ↓
            法术        神通        神识
              │           │           │
              └───────────┼───────────┘
                          ↓
                       战斗表现
```

### 1.1 各系统"明确不负责什么"

这张表与上面同等重要——**边界靠"不做什么"来守**。

| 系统 | 不负责 |
| --- | --- |
| 修行 | 不做 BD 机制（那是神通）；不做具体法术内容（那是法术）；不做自动化与战斗 AI（那是神识） |
| 法术 | 不做 BD 构筑（"万剑诀每击中一个敌人下次伤害 +10%"这类**属于神通**，不是法术本体）；不做系统解锁与成长阶段 |
| 神通 | 不做系统自身的规则进化（规则成长来自修行 Node 与神识）；不做自动化；不新增数值乘区（见 §7） |
| 神识 | **不变成第五种攻击属性**；不提供直接的伤害数值成长；不做 BD 规则本身（它只控制"怎么执行"） |

## 2. 资源与货币

### 2.1 一系统一主货币

四个系统各有一套**独立货币**，不使用一个"万能修仙点数"同时升级所有系统。

| 系统 | 主货币（暂名） | 用途 |
| --- | --- | --- |
| 修行 | **修为** | 点修行 Node、境界突破 |
| 法术 | **法术灵韵** | 法术的习得与升级 |
| 神通 | **神通真意** | 悟道等级、槽位解锁、槽位升级、Roll |
| 神识 | **神识精粹** | 神识系统的控制力成长 |

既有货币的角色：

- **灵石（`gold`）**：保留给**非四大系统**（锻造、宠物等）以及杂项。它**退出**法术这条线。
- **灵核（`core`）**：**首杀专属、记账型**货币，机制与校验保持不变（它是"累计投放量必须等于首杀数 +
  调试发放量"的那种硬通货，不受本方案影响）。

> 货币名称是**暂名**，统一命名的时点在内容阶段；本方案只定义职责与归属。

### 2.2 产出口：只有击杀

四种新货币**全部靠击杀敌人掉落**，由**修行 Node 逐个解锁掉落渠道**，再由修行 Node 与其它系统**强化掉率与产量**。

```text
修行 Node  →  解锁某系统  →  该系统的货币开始掉落
修行 Node  →  该货币掉落 +X% / 精英额外 +1 / BOSS 掉落提升
神识等系统 →  进一步提高获取效率
```

- 工程现状里唯一的"非战斗产出口"（参悟的打坐吐纳）**随参悟一起删除**，因此产出口收敛成一条。
- 由此得到一条必须遵守的分工：**Node 负责"开启与强化资源获取渠道"，其它系统负责"进一步提高效率"**。
- 未解锁的系统，其货币**不掉落**——成长系统不是一开始就把所有货币全部掉出来。

### 2.3 红线

```text
✅ 修行 Node → 法术灵韵掉落 +20%
✅ 神识      → 自动收取法术灵韵
✅ 神通      → 剑法伤害 +30%

❌ 神通升级需要法术灵韵
❌ 法术升级需要神通真意
❌ 神识升级需要修为
❌ 修行 Node 又需要神识精粹
```

**系统之间可以互相增强，但不要互相吞并**：跨系统消耗会织出一张复杂的资源网，
把每种货币的"归属感"消掉。跨系统消耗是**禁止项**，需要破例时必须先改本文档。

## 3. 修行

### 3.1 三名分立

系统名、资源名、阶段名是三件事，不要混用：

```text
系统：修行
资源：修为
阶段：境界
```

玩家的成长体验：**不断修行 → 积累修为 → 在修行道路上前进 → 突破境界 → 获得更高层次的能力。**

### 3.2 Node 是长期成长载体

修行 Node 是整个游戏**最主要的长期 Node 树**：

- **横向原则上不设长度限制；纵向最多 5 行**（与现有 `talent_grid_rows = 5` 一致）。
- 左早右晚；允许分支、汇合、跨行连接；不要求严格线性。
- 前置的语义是"**任意一条点亮即可**"（OR），不是"全部点亮"。

### 3.3 Node 的六种类型

| 类型 | 例子 | 备注 |
| --- | --- | --- |
| A. 基础属性 | 攻击 +N、气血 +N、暴击 +1% | 最基础的数值成长 |
| B. 资源获取 | 法术灵韵掉落 +10%、神通真意掉落 +10% | **系统未解锁时，这类 Node 不该提前大量出现** |
| C. 系统解锁 | 解锁法术 / 神通 / 神识 | 解锁后该系统才进入游戏循环 |
| D. 功能解锁 | 解锁悟道能力、解锁自动化功能 | 面向"玩法开关"而不是数值 |
| E. 境界突破 | 【筑基突破】【金丹突破】 | **最高优先级的特殊 Node** |
| F. 特殊永久选择 | 命格强化、槽位结构改造 | 可以制造长期 build 差异，但**必须非常克制** |

> **修行 Node 的主要职责不是做 BD。** 它可以存在少量"特殊永久选择"来制造差异，
> 但 BD 的主要职责属于神通。

**境界突破 Node 是最高优先级的里程碑**，它承担 §3.4 的四职责。

### 3.4 境界的四职责

境界不是"一个数值台阶"，它同时承担四件事：

```text
① 数值成长阶段   ② 内容解锁阶段   ③ 系统成长阶段   ④ 角色视觉进化阶段
```

突破境界必须产生**明显的成长跃迁**——不能只是"攻击力 +10%"，而应该是：

```text
基础成长提升 + 新的内容 + 新的能力 + 新的视觉表现
```

玩家应该明确感到"我突破了一个新的生命层次"。

**每个大境界拥有一个境界专属能力**：

- **自动生效**；
- **不占神通槽**；
- **不是玩家的 build 选择**——它是角色本身的能力。

> ⚠️ 具体能力内容**尚未裁定**。原讨论稿给的示例与现有/新系统有重叠（"分身"撞剑二十三的影分身、
> "自动化"撞神识、"概率额外释放"撞术神通），必须先划清再定稿。见 §11 待碰清单。

### 3.5 境界的驱动方式（本轮改造）

- **境界突破由修行树上的「境界突破 Node」承担，消耗「修为」**——不再是"在法术页里花灵石顺序买"。
- 境界仍然**解锁技能书序**（这一条不变）：境界决定"能习得哪些法术"。
- 突破成功后：基础属性提升 + 获得境界固有能力 + 解锁该阶段内容 + 角色外观变化。

### 3.6 视觉进化

**同一个土豆妖持续成长，不是每次换成一个完全不同的角色。** 视觉变化要有连续性
（芽 → 根 → 灵纹 → 妖丹 → 灵体 → 神魂 → 法相），但**始终保留"这是一颗土豆"的核心识别**。

### 3.7 境界词汇（正式口径）

**修仙五境：炼气 / 筑基 / 金丹 / 元婴 / 化神。**

- 「凡妖」是开局"还没入道"的**叙事状态**，**不占一档**（对应现有 `realm_0..4` 五档）。
- 「小妖 / 妖将 / 妖王 / 妖尊 / 妖圣」**不再作为境界名**；是否转作"怪物强度分级"的词汇见 §11。

## 4. 法术

### 4.1 定位

法术解决 **"玩家会哪些战斗手段"**，它是**战斗内容库**，**不是主要 BD 系统**。

### 4.2 永久学习，不设装备槽

**法术一旦学习，永久进入法术库。**

不设"5 个法术槽、每次换 5 个"，也不在境界突破时重新选择法术。理由：游戏已经有修行路径、
神通槽位、神通选择三层决策，法术再做成装备槽会让操作负担变成四层。

### 4.3 法术有等级

```text
学习法术 → Lv.1 → 升级 → Lv.2 → Lv.3 → …
```

升级消耗**法术专属货币（法术灵韵）**，与其它系统不交叉。

### 4.4 自动释放

基础战斗状态下，**所有已学会的法术都进入自动战斗循环**，玩家不需要每次手动选择放哪个。
释放由系统按冷却、目标、法术规则、（后续的）神识逻辑与神通改变自动执行。

> ⚠️ **工程现状**：法术释放目前是"冷却就绪 + 有合法目标 → 全放"，**没有任何跨法术的优先级**。
> 本文档确认释放决策**将来**由神识承担（§6.3），v1 不做。

### 4.5 三轴标签体系

法术拥有标签，**标签是神通与神识对法术做定点构筑的唯一抓手**：

| 轴 | 作用 | 取值（内容阶段定稿） |
| --- | --- | --- |
| **元素** | 炎 / 霜 / 雷 / 风 这类属性归属 | 示例：风 / 雷 / 霜 / 炎 |
| **流派** | 体系归属 | 示例：剑法 / 血法 / 雷法 … |
| **形态** | 命中方式 | 示例：单体 / AOE / 持续 / 控制 |

- 一个法术可以同时拥有**多条**标签（跨轴、同轴多条都可以）。
- 标签的枚举取值表与"逐个法术打标"属于内容阶段；**轴的集合（三轴）已确认**。
- 现有 `SwordSkill` 表**没有标签列**，落地时要新增。

### 4.6 法术不负责核心 BD

```text
✅ 法术：万剑诀 = 释放剑雨
❌ 法术：万剑诀每击中一个敌人，下一次伤害 +10%
   → 这类机制属于【神通】
```

一句话：**法术负责"是什么技能"，神通负责"这个技能如何被构筑"。**

## 5. 神通（悟道）

### 5.1 定位

神通是《土豆修仙》的**主要 BD 系统**，四个系统里最应该承担 build 的那个。
核心问题：**"我准备怎么战斗？"**

与法术的体验差异要**非常明确**：

> **法术 = 知识库——确定性获得、稳定升级。**
> **神通 = 悟道 / 机缘——随机获得、赌博式选择。**

> ⚠️ **命名**：本文档的「神通」指 BD 系统。工程里原有的「神通」（普攻概率触发、不自动释放的法术）
> **改回旧称「真诀」**（历史上就叫这个名字）；玩家可见文案只有两处需要改，详见 §10。

### 5.2 三类神通

| 类型 | 定位 | 典型效果 |
| --- | --- | --- |
| **命神通** | **核心 Build / 规则级机制**。数量最谨慎 | 满足某条件后整个 Build 变化；某类法术获得全新运行方式；某个战斗规则改变。例：「装备 3 个剑法相关神通时，剑法伤害 ×1.5」 |
| **身神通** | **角色本身的强化与通用战斗机制** | 属性、生存、资源循环、通用触发。例：攻击 +20%、受击后获得护盾、击杀后回血。**不该大量改变某个具体法术的核心行为** |
| **术神通** | **强化法术以及法术体系**（法术与 BD 之间的桥梁） | 所有剑法伤害 +30%；剑法有 10% 概率额外释放；AOE 法术范围 +20% |

原则：**命神通决定"我是什么流派"。**

### 5.3 获得方式：Roll（悟道）

神通**不通过学习获得，而是通过 Roll**。

```text
通关 / 修行到一定境界（第 3 境界 · 金丹）
        ↓
获得神通槽 → 消耗神通真意 → 选定一个槽位 → Roll
        ↓
从该类型神通池中随机出 3 个（各自带品质）
        ↓
玩家 3 选 1  →  直接装备到该槽位
```

- **不做仓库**：选中就直接装备，换上去就顶掉旧的（§5.7）。
- 玩家每次 Roll 都在回答一个很明确的问题：**"我要不要把这一格变成这个东西？"**

### 5.4 品质的语义（重要）

**品质不是"同一个效果乘一个系数"的数值递进档**，而是**"效果分量"的分层**：

| 档 | 设计意图 |
| --- | --- |
| 绿 / 蓝 / 金 | **常规品质** |
| **彩** | **特殊高品质档**——极低概率的稀有极品，且**由悟道等级解锁后才进入可能** |

三层语义：

```text
低档   → 简单直接的数值/属性强化
中高档 → 特化的效果
彩     → 特殊规则版本（"规则级"的效果）
```

**每个（神通 × 品质）都是一个独立的设计单元，各自有自己的库**——而不是"一个 effect + 一个品质系数"。

以命神通为例（**示例，非定稿**）：

```text
低档：所有剑法威力 +X%
中高档：剑法有概率双倍
顶级：指向具体技能——「万剑诀会同时释放 3 次，所有剑法威力提升 300%」
```

身神通与术神通同理：低档可以简单加属性，中高档是特化效果。

> ⚠️ **具体词条属于专门的设计方案**，本文档只定"分层原则与各档的设计意图"。
> 这条裁定的**结构性后果**：配置形态上"神通 × 品质"各占一行（不是一个效果乘品质系数），
> 因此内容量与平衡面都成倍增加——排期时要正视。
>
> ⚠️ **金色/彩色的"附加机制不能无限复杂"**，否则单个神通会变成一个小系统、平衡难度失控。

### 5.5 两条成长轴必须分开

这是整个神通系统最关键的结构：

```text
槽位等级  = 稳定成长（低波动、确定收益、持续投入）
神通本体  = 随机内容（Roll 得到，直接替换）
```

- **神通本体不升级**。玩家 Roll 到一个新神通，**成长不会丢**——因为成长长在槽位上。
- 这与"槽位等级不会因为 Roll 改变"是同一条规则的两面。少了它，玩家会觉得"我之前升级都白费了"。

**槽位等级的含义**：这个位置**对神通力量的承载能力**（一个"神通强度系数"）。
于是最终效果由三件事共同决定：

```text
槽位等级  ×  神通品质  ×  神通本体
```

### 5.6 神通真意的三种消费（三层资源漏斗）

神通真意是该系统**唯一货币**，流向三个层次，心理完全不同：

```text
                 神通真意
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
       悟道成长     槽位成长      Roll
          │          │          │
      大额投入      稳定投入      随机投入
          │          │          │
      提升长期上限   稳定变强      追求极品
       "我必须把      "这个肯定     "我现在有余钱
        系统养起来"    不亏，慢慢升"  了，来一把"
```

**① 悟道等级（第一优先级）**

- 决定**品质池的开放与概率上限**——它不是"金色概率 +2%"这种无聊的线性加成，而是
  **逐渐打开整个博彩系统的能力**：

```text
悟道 Lv.1  绿 / 蓝
悟道 Lv.2  蓝色概率提升
悟道 Lv.3  金色加入
悟道 Lv.4  彩色加入
悟道 Lv.5  彩色概率提升
悟道 Lv.6  Roll 结果质量提升
```

- **前期不让玩家接触完整的神通博彩体验**：刚开启神通时只能获得普通品质，
  先凑几个能用的，把悟道练起来。这样玩家不会一进来就想去凹小概率。
- 悟道等级**昂贵、阶段性、值得长期攒**（大台阶）；槽位升级**小步长、可预期**（"存够了就升"）。
  两者的成本曲线必须**明显不同**。

**② 槽位成长**

- **解锁**：神通槽**全部由神通系统用神通真意解锁**（修行 Node 不直接给槽，只改 Roll 规则）。
- **升级**：消耗神通真意，提升该槽位的神通强度系数。这条轴**不受神通替换影响**。

**③ Roll**

- **基础成本固定**，不随次数递增（身后已经有槽位升级这条成本曲线，不需要 Roll 也做成成长）。
  降低 Roll 成本的手段来自**修行 Node 与神识**（"基础固定 + 修正来源"）。

### 5.7 Roll 的规则与保底

- **3 选 1**：从对应类型的神通池中抽 3 个，各自带品质，玩家选 1 个直接装备。
- **重复练到同一个神通不是废结果**——它是追求更高品质的途径。
- **重复即替换**：再次 Roll 并选中后，原来装备在槽位上的那份**直接销毁**，无仓库、无回收。
  成长不丢（槽位等级保留），所以不会产生"之前的投入白费了"的感觉。
- **上限保底**：**连续 5 次 Roll 内，至少出现一次「当前已开放的最高品质」**。
  - 保底针对**本次 3 选 1 的三个选项**——玩家始终是在 3 选 1，而不是系统直接发奖。
  - **彩色未开放时保底不计不改**；彩色开放后，保底指向彩。

### 5.8 系统自身不产生新的系统规则

**神通系统不通过 Roll 过程自身产生新的系统规则。** 它内部只保留三样东西：

```text
悟道等级  +  槽位解锁  +  少量关键能力（3～5 个）
```

不要出现"神通系统技能树 / 天赋树 / 强化树 / 科技树"。系统规则的成长来源是
**修行 Node + 神识 + 神通系统内部的少量固定成长**。

分工写清楚：

| 谁 | 负责什么 |
| --- | --- |
| **修行 Node** | 永久、规则型、结构型的改变：Roll 成本、保底次数、品质概率、候选数量、指定分类 |
| **神识** | "越来越会悟道"：锁定结果、重 Roll 一个、排除标签、额外候选位 |
| **神通系统自身** | 悟道等级、槽位解锁、槽位升级、少量关键能力 |
| **Roll** | 消耗资源、追求结果 |

### 5.9 表现原则（出金/出彩的爽感）

神通系统本质上是 `概率 → 期待 → 揭示 → 结果 → 奖励`，这条心理节奏值得做强表现。

- **揭示分三段**：先出现三个神通轮廓 → 品质逐个揭示（绿 / 蓝 / 金 / 彩）→ 三张完整神通出现、玩家选择。
- **金与彩的演出必须有本质差别**：金 = 强烈光效 + 音效 + 屏幕反馈；彩 = 特殊演出 + 独立音效 +
  屏幕/背景变化 + 图标特殊表现。
- **彩色出现的瞬间本身就是奖励**——即使玩家最终没选它，也该觉得"卧槽，出了"。
- 可以借鉴赌博游戏的"差一点"反馈（如"绿/金/金"强化下一次期待）。
- ⚠️ **前提**：本作是**非氪金单机**，这些设计**不是诱导付费**，而是让"后期用冗余资源主动追求博彩快感"变得好玩。
  玩家赌的是**已经积累出来的游戏内资源**。

### 5.10 终极体验

> **不是被概率折磨，而是在操纵概率。**

```text
早期：随机性高
中期：随机性可控
后期：随机性高度可控（但仍保留一点不确定性）
```

后期玩家可以做到"我要术神通 + 剑法 + 高品质 → Roll"，出现的仍可能是蓝/金/彩之一——
**多了一点，就是"赌"的快乐**。

因此本系统的终局定位是：

> **它是资源消耗型的长期博彩成长系统，而不是"低概率逼玩家反复抽"。**
> 后期它是**回收冗余资源**的健康出口（比"无限升级属性"的数字膨胀好）。

### 5.11 分阶段体验

| 阶段 | 玩家的目标 | Roll 的角色 |
| --- | --- | --- |
| 前期 | "我先有神通" | 拿到能用的就停，悟道优先 |
| 中期 | "我的神通体系越来越完整" | Roll 是辅助行为 |
| 后期 | "追求极品" | 悟道与概率拉满，大量 Roll 追求金/彩与理想组合 |

## 6. 神识

### 6.1 定位

**神识不是第四套攻击属性。** 它解决：

> **"角色能同时理解、控制和自动处理多少事情？"**

保持的方向是：**更聪明 → 更自动 → 更高效 → 更强的执行逻辑**，
而不是"神识 +10 → 攻击力 +10"。

### 6.2 v1 范围：只做「神通 Roll 的控制力」

神识 v1 = **让玩家越来越会控制随机性的那套能力**：

```text
锁定一个选项 / 重新 Roll 一个选项 / 排除一个标签 / 指定一个标签 / 额外候选位
```

- 主题上非常统一：**修行 Node 是"悟道环境变好了"，神识是"我自己越来越会悟道了"。**
- 与神通同期上线最自然——两者天生咬合。
- **形态**：独立系统，自有货币（神识精粹）+ 修行 Node 解锁 + 独立页签。

**v1 不做**（列入后续扩展）：

| 后续块 | 内容 | 前置依赖 |
| --- | --- | --- |
| 自动化 | 自动收取产物、自动处理资源 | 把现有零散的自动化（生根、自动普攻、`auto_intent` 那类）统一收编到神识名下 |
| **战斗逻辑** | 释放优先级与条件门控：优先 Boss、敌人 ≥5 优先 AOE、BOSS 出现时保留爆发、优先维持某个 Buff | ⚠️ **会动战斗核心**：现在 `CastSkills` 是"冷却好就全放"，而期望模型 `LevelCurve` 与对账基线 `CombatProbe` 都依赖实际出手频率，**必须同步否则静默分叉**。详见 [../design/combat.md](../design/combat.md) |
| 多任务 / 后台收益 | 同时跑多个自动化任务、离线收益 | ⚠️ 与现状冲突：游戏当前**明确"离线不产出"**；引入前要先决定是否做离线结算 |

### 6.3 神识与随机性的关系（写死的原则）

> **我们不追求"让玩家永远抽不到想要的东西"。恰恰相反——随着成长，玩家越来越能够控制概率。**

这条反过来约束了神通系统的设计：**不要把随机性做成玩家无法干预的黑箱**，而要留出神识与 Node 的干预接口。

## 7. BD 与伤害乘区

神通必须服从现有战斗公式，**不许随意创造新乘区**（口径见 [../design/combat.md](../design/combat.md)）。

| 神通类型 | 进哪个乘区 |
| --- | --- |
| **普通神通**（属性 +20%、剑法伤害 +30%、雷法伤害 +40% …） | **General Damage Bonus**（现有的加算池——`generic_damage` / `atk_percent` 那条，`1 + Σ`） |
| **命神通 / 核心 Build 神通**（"满足某条件时剑法伤害 ×1.5"） | **Build Multiplier**（DMG3 的 Build 乘区） |

```text
普通神通        → 数值成长（General）
命神通 / 核心   → Build 规则（Build）
```

这是防止 BD 系统失控的重要边界。**品质词条的乘区归属按同一条判据**：
"它就是个数" → General；"它改变了这一发的规则/条件" → Build。

> ⚠️ 部分身神通与命神通的写法需要**战斗事件**（"受到伤害后获得护盾""击杀敌人后恢复生命"），
> 而战斗事件总线（`combat.md` §8）**尚未实现**，触发器白名单目前只有两个事件。见 §10。
>
> ⚠️ 原"易伤（`vulnerable`）将来由剑意授予某个技能分支"的待办，**改挂到术神通**（参悟已删除）。

## 8. 系统关系与一条成长时间线

```text
                        【修行】
                           │
                   修为 + 修行 Node
                           │
         ┌─────────────────┼─────────────────┐
         ↓                 ↓                 ↓
      解锁法术           解锁神通           解锁神识
         │                 │                 │
     法术灵韵           神通真意           神识精粹
         │                 │                 │
     法术习得/升级      悟道/槽位/Roll      控制力成长
         │                 │                 │
         └────────────┬────┴───────┬─────────┘
                      ↓             ↓
                    战斗          自动化
```

由此形成的增量循环：

> **解锁新资源 → 新系统成长 → 反过来加速资源获取 → 再推进修行。**

示例时间线：

| 阶段 | 发生什么 |
| --- | --- |
| **炼气** | 修行 → 获得修为 → 点 Node → 基础属性；Node 解锁**法术** → 法术灵韵开始掉落 → 学会第一个法术 |
| **继续修行** | Node 强化法术灵韵掉落 → 法术升级；Node 解锁**神通** → 神通真意开始掉落 → 先凑几个能用的神通 |
| **筑基** | 修行树多个 Node 汇聚 → 【筑基突破】→ 属性跃迁 + 筑基固有能力 + 新内容 + 外观变化 |
| **金丹** | 神通系统正式开启（第 3 境界）：悟道等级、槽位解锁、开始 Roll；Node 继续改 Roll 规则 |
| **形成 Build** | 法术：剑法 A / 剑法 B / 雷法 A；术神通：剑法强化 + 额外释放；命神通：剑心类核心机制；身神通：暴击 / 攻速 / 击杀恢复；神识：优先放某个法术、Boss 出现时保留爆发 |
| **后期** | 悟道与概率拉满 → 神识控制力完善 → 大量 Roll 追求金 / 彩与理想组合（回收冗余资源） |

两个玩家可以拥有**相同的法术库**，但战斗表现完全不同——这就是神通作为 BD 系统的意义。

## 9. 扩展原则

未来增加新系统（炼器、炼丹、日月精华…）时，不得破坏以上四系统边界。新系统首先回答：

> **它解决哪个新的玩家问题？**

而不是"这里还能塞什么成长属性"。如果它只是"攻击 +10%、气血 +100"，那么优先考虑
**进入现有系统**，而不是新建系统。

三条必须守住的：

1. **一个系统只有一个核心问题**（四系统的问题见 §1）。
2. **不要重复造系统**：❌ 法术自己做一套 Build Tree ❌ 神通再做一套技能树
   ❌ 神识再做一套攻击强化树 ❌ 修行再做一套完整 BD 系统。
3. **Node 是长期成长载体，不是所有系统的技能树**——尤其不要让"所有游戏内容最后都塞进 Node"。
