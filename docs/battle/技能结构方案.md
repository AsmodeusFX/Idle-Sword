
# 《土豆修仙》Skill / Effect / Buff 技能结构方案 V1.0

## 1. 设计目标

本方案用于定义《土豆修仙》战斗系统中：

- `skill.csv`
- `effect.csv`
- `buff.csv`

三类数据的职责、引用关系以及运行时执行方式。

核心原则：

> **Skill 是技能释放控制层。**
>
> **Effect 是瞬时行为层。**
>
> **Buff 是时间化行为层。**

三者不互相承担对方职责。

---

# 2. 三层职责

## 2.1 Skill：技能释放控制

Skill 不负责描述“释放之后具体发生什么”。

Skill 只负责：

> **这个技能现在能不能释放，以及释放时确定谁是目标。**

Skill 主要包含：

- 是否可释放
- 释放条件
- 目标选择
- CD
- 能耗
- 施法距离
- 施法前置条件
- 基础释放时间
- 释放后进入 CD
- 引用哪些 Effect
- 引用哪些 Buff

例如：

```text
御剑术

CD：8秒
能耗：20
目标：随机敌人
最大距离：20
```

Skill 本身不写：

```text
造成 200% 攻击力伤害
发射 3 把飞剑
造成流血
2 秒后再次攻击
持续 5 秒
```

这些全部由 Effect / Buff 完成。

---

# 3. Effect：瞬时行为

Effect 表示：

> **某个时刻发生的一次性行为。**

Effect 没有自己的持续时间概念。

典型 Effect：

```text
造成伤害
治疗
生成飞剑
击退
施加 Buff
移除 Buff
恢复能量
刷新技能 CD
增加临时属性
触发另一个技能
生成投射物
```

例如：

```text
E001
Action = DealDamage
DamageRate = 2.0
```

表示：

> 执行一次 200% 攻击力伤害。

---

# 4. Buff：时间化行为

Buff 表示：

> **一个拥有时间轴、状态和生命周期的 Effect 容器。**

Buff 不是简单的“加属性”。

它可以表达：

```text
持续 5 秒
↓
第 0 秒触发一次
↓
第 1 秒触发一次
↓
第 2 秒触发一次
↓
受到攻击时触发
↓
第 5 秒结束
```

因此 Buff 可以包含：

- Duration
- Delay
- Timeline
- Trigger
- Tick
- Condition
- OnApply
- OnRemove
- OnInterrupt
- Stack
- Refresh
- Pause
- Resume

例如：

```text
B001：流血

持续时间：5秒

Timeline：
0秒 → 立即造成一次流血伤害
1秒 → 造成一次流血伤害
2秒 → 造成一次流血伤害
3秒 → 造成一次流血伤害
4秒 → 造成一次流血伤害
5秒 → Buff结束
```

---

# 5. 三者关系

推荐采用：

```text
                     Skill
                       │
            ┌──────────┴──────────┐
            ↓                     ↓
         Effect                  Buff
      瞬时行为                时间化行为
            │                     │
            │              ┌──────┴──────┐
            │              ↓             ↓
            │          Timeline       Trigger
            │
            └──────────────┬──────────────┘
                           ↓
                     Combat Event
```

一个 Skill 可以同时引用多个 Effect 和 Buff。

例如：

```text
Skill：雷霆剑

Effects：
E001 造成伤害
E002 击退
E003 生成雷电

Buffs：
B001 雷霆领域
```

释放技能后：

```text
Skill
 ↓
判断可以释放
 ↓
选择目标
 ↓
执行 Effect
 ↓
E001 伤害
E002 击退
E003 生成雷电
 ↓
Apply Buff
 ↓
B001 雷霆领域开始运行
```

# 6. Skill 数据结构

建议 V1：

```text
skill.csv
```

核心字段：

| 字段 | 含义 |
|---|---|
| skill_id | 技能 ID |
| name | 技能名称 |
| enabled | 是否启用 |
| target_type | 目标类型 |
| target_rule | 目标选择规则 |
| range | 释放距离 |
| cooldown | CD |
| energy_cost | 能耗 |
| cast_time | 释放时间 |
| condition | 释放条件 |
| effect_ids | 瞬时 Effect |
| buff_ids | Buff |
| interruptible | 是否可被打断 |
| description | 描述 |

其中：

```text
effect_ids
buff_ids
```

都只是引用。

Skill 不保存具体效果逻辑。

# 7. Skill 的核心生命周期

Skill 的运行过程统一为：

```text
Check Cast
    ↓
Target Resolution
    ↓
Cast Start
    ↓
Cast / Interrupt Check
    ↓
Cast Complete
    ↓
Execute Effects
    ↓
Apply Buffs
    ↓
Start Cooldown
```

例如：

```text
御剑术

Check
↓
CD = 0？
↓
能量 >= 20？
↓
存在目标？
↓
选择目标
↓
开始释放
↓
完成
↓
E001：生成飞剑
↓
E002：造成伤害
↓
B001：附加剑意状态
↓
进入 8 秒 CD
```

---

# 8. 为什么 Skill 可以同时引用 Effect 和 Buff

这里保留原来的设计，不建议取消。

原因很简单：

### Effect 适合表达

```text
释放技能
→ 立即造成伤害
→ 立即击退
→ 立即生成投射物
```

### Buff 适合表达

```text
释放技能
→ 进入一个持续状态
→ 状态存在 5 秒
→ 每秒执行一次行为
```

两者都是“技能释放后的结果”，但生命周期完全不同。

因此：

```text
Skill
 ├── Effects
 └── Buffs
```

是合理的。

---

# 9. Buff 与打断机制

这是本结构非常重要的一点。

Buff 作为时间轴容器，可以天然承载：

```text
Delay
Timeline
Trigger
Duration
Interrupt
```

例如：

## 蓄力斩

Skill：

```text
CD = 10
Target = Enemy
Buff = B001
```

Buff：

```text
B001 蓄力状态

Duration = 2s

Timeline：

0s
开始蓄力

2s
触发 E001：巨剑攻击
```

如果角色在 1 秒时受到打断：

```text
Skill
 ↓
Apply B001
 ↓
B001 Timeline
 ↓
1秒
 ↓
Interrupt
 ↓
B001 Remove
 ↓
后续 Effect 不执行
```

这样就不需要在 Skill 中写：

```text
if interrupted:
    cancel damage
```

而是：

> **Skill 负责启动 Buff，Buff 自己负责自己的生命周期。**

---

# 10. Skill 的“释放”与“效果执行”必须分离

这是整个结构最重要的边界之一。

Skill：

```text
我能不能释放？
```

Effect：

```text
释放后现在发生什么？
```

Buff：

```text
释放后的这个行为在未来怎么继续发生？
```

因此：

```text
Skill = Cast Controller
Effect = Instant Action
Buff = Timed Action
```

# 11. Effect 数据结构

推荐：

```text
effect.csv
```

不要让 Effect 表直接长成：

```text
effect_id
damage
heal
knockback
projectile
...
```

这种方式会导致大量空字段。

建议采用：

```text
effect_id
effect_type
param_1
param_2
param_3
target_rule
condition
```

例如：

```text
E001
effect_type = DealDamage
param_1 = 2.0
```

```text
E002
effect_type = Knockback
param_1 = 5
```

```text
E003
effect_type = SpawnProjectile
param_1 = sword_projectile
param_2 = 3
```

代码层：

```text
EffectExecutor
    ↓
根据 effect_type
    ↓
调用对应 Effect Handler
```

例如：

```text
DealDamageEffect
KnockbackEffect
SpawnProjectileEffect
ApplyBuffEffect
RemoveBuffEffect
TriggerSkillEffect
```

# 12. Buff 数据结构

Buff 不建议只做成：

```text
buff_id
duration
effect_ids
```

因为后续 Timeline / Trigger 很快会出现。

建议拆成：

```text
buff.csv
buff_timeline.csv
```

而不是把所有东西全部塞进 buff.csv。

---

## 12.1 buff.csv

负责 Buff 的基本生命周期：

```text
buff_id
name
duration
max_stack
stack_rule
refresh_rule
interruptible
pauseable
on_apply_effects
on_remove_effects
```

例如：

```text
B001
name = 蓄力
duration = 2
max_stack = 1
interruptible = true
```

---

## 12.2 buff_timeline.csv

负责：

> Buff 在时间轴上的具体行为。

例如：

```text
buff_id
time
trigger_type
effect_ids
condition
```

数据：

```text
B001 | 0.0 | OnApply | E010
B001 | 1.0 | Timeline | E011
B001 | 2.0 | Timeline | E012
```

表示：

```text
Buff开始
 ↓
0秒 → E010
 ↓
1秒 → E011
 ↓
2秒 → E012
 ↓
Buff结束
```

---

# 13. Trigger 不应该全部写死在 Buff

Timeline 和 Trigger 是两个不同概念。

### Timeline

按时间触发：

```text
0秒
1秒
2秒
```

### Trigger

按事件触发：

```text
OnHit
OnDamage
OnCrit
OnKill
OnTakeDamage
OnEnemyDeath
OnSkillCast
```

因此可以统一成：

```text
BuffTrigger
```

例如：

```text
B002

Duration = 5s

Trigger:
OnHit
→ E020

Trigger:
OnKill
→ E021

Timeline:
3s
→ E022
```

这样一个 Buff 可以同时拥有：

```text
时间行为
+
事件行为
```

这也是 Buff 和普通 Effect 最大的区别。

# 14. 推荐的数据关系

最终结构：

```text
skill.csv
   │
   ├──────────────→ effect.csv
   │
   └──────────────→ buff.csv
                         │
                         ├──→ buff_timeline.csv
                         │
                         └──→ effect.csv
```

因此：

```text
Skill
 ├── Effect
 │     └── Instant Action
 │
 └── Buff
       ├── Timeline
       │     └── Effect
       │
       └── Trigger
             └── Effect
```

这套结构非常重要：

> **Effect 是最终执行单元。**

Skill 可以触发 Effect。

Buff 可以触发 Effect。

Trigger 可以触发 Effect。

未来其他系统也可以触发 Effect。

最终战斗系统只需要理解：

```text
ExecuteEffect(effect_id, context)
```

---

# 15. 不要让 Skill 直接产生战斗行为

例如：

错误：

```text
Skill：
damage = 200%
knockback = 5
bleed = true
```

正确：

```text
Skill：
effect_ids = E001|E002
buff_ids = B001
```

然后：

```text
E001 → DealDamage 200%
E002 → Knockback 5
B001 → Bleed 5秒
```

这样技能只是一个组合器。

# 16. 技能参数成长与 Skill 表的关系

Skill 自身仍然拥有基础参数：

```text
cooldown
energy_cost
range
cast_time
```

这些属于：

> **Skill 是否可以释放以及释放规则。**

因此可以被 Skill Attribute / Skill Parameter Modifier 修改。

例如：

```text
基础 CD = 10秒
```

节点：

```text
御剑术 CD -30%
```

运行时：

```text
RuntimeSkill.cooldown
=
BaseCooldown × (1 - CooldownReduction)
```

而：

```text
剑数量 +1
```

也可以作为 Skill Parameter：

```text
RuntimeSkill.projectile_count
=
BaseProjectileCount + Modifier
```

但注意：

> `projectile_count` 虽然不是 Skill 的“释放条件”，仍然属于 Skill 的运行参数。

它与 Effect 的区别是：

```text
Skill Parameter
= 决定 Effect 执行时使用什么参数

Effect
= 决定实际执行什么行为
```

例如：

```text
Skill：
projectile_count = 3

Effect：
SpawnProjectile
```

最终：

```text
SpawnProjectile
读取 RuntimeSkill.projectile_count
→ 生成 3 个
```

# 18. 与 DMG2 的关系

这套结构可以很好地接入目前已经确定的 DMG2。

Skill：

```text
Skill Cast
```

Effect：

```text
DealDamage
```

产生：

```text
AttackEvent
```

然后：

```text
AttackEvent
 ↓
DMG1
 ↓
DMG2
 ↓
DamageEvent
 ↓
DMG3
 ↓
Apply Damage
 ↓
OnHit / OnCrit / OnKill
```

如果 Effect 是：

```text
TriggerSkill
```

则：

```text
Effect
 ↓
New Skill Cast
 ↓
New AttackEvent
 ↓
重新进入 DMG2
```

如果 Effect 是：

```text
ApplyBuff
```

则：

```text
Effect
 ↓
BuffSystem
 ↓
创建 Buff Instance
 ↓
Timeline / Trigger
 ↓
继续产生 Effect
```

所以最终形成：

```text
Skill
 ↓
Effect / Buff
 ↓
Combat Event
 ↓
AttackEvent
 ↓
DMG2
 ↓
Effect / Buff / Trigger
 ↓
新的 Combat Event
```

整个系统可以自然形成事件链。

# 19. 三种数据不要互相污染

最终明确以下边界：

### Skill 不负责

```text
具体伤害
具体 Buff 行为
具体 Timeline
具体 OnHit 行为
具体 OnCrit 行为
```

### Effect 不负责

```text
技能 CD
技能能耗
技能是否可以释放
技能目标选择
技能释放条件
```

### Buff 不负责

```text
技能 CD
技能能耗
技能本身是否可释放
```

Buff 只负责自己的生命周期和行为。

# 22. 最终架构原则

《土豆修仙》的 Skill 系统最终采用：

```text
                Skill
                  │
       “是否可以释放”
                  │
          ┌───────┴───────┐
          ↓               ↓
       Effect            Buff
     瞬时行为          时间化行为
          │               │
          │        ┌──────┴──────┐
          │        ↓             ↓
          │     Timeline       Trigger
          │        │             │
          └────────┴──────┬──────┘
                          ↓
                       Effect
                          ↓
                    Combat Event
                          ↓
                    AttackEvent
                          ↓
                         DMG2
```

核心定义：

> **Skill 是“释放控制器”。**
>
> **Effect 是“瞬时执行单元”。**
>
> **Buff 是“拥有生命周期的 Effect 容器”。**
>
> **Timeline / Trigger 决定 Buff 什么时候再次执行 Effect。**
>
> **最终所有真正发生的战斗行为，都落到 Effect。**

这样设计后，技能本身会非常干净。

一个技能可以只是：

```text
Skill
= Target + CD + Cost + Condition + Effect引用 + Buff引用
```

而真正复杂的技能：

```text
Skill
→ Effect
→ Buff
→ Timeline
→ Effect
→ Trigger
→ Effect
→ AttackEvent
→ DMG2
```

也仍然不需要在 Skill 层增加大量特殊字段。

这会比较适合后续用 **CSV + 编辑器 + Claude Code** 持续扩展。
