## 0. 三句话读懂这套技能

1. 一个法术 = **Skill（能不能放、放谁）+ Effect（放出去这一刻做什么）+ Buff（接下来几秒做什么）**。
   配置上是**五张表**：`SwordSkill` / `SkillEffect` / `SkillBuff` / `SkillBuffTimeline` / `SkillBuffTrigger`。
2. **所有真正发生的战斗行为都落在 Effect 上**——包括由 Buff 的时间轴 / 事件触发器派生出来的那些
   （环绕飞剑、暴击缩冷却、影分身复制）。触发器表之所以能工作，是因为它引用的是"一条真实的 Effect 行"。
3. 一个法术最多有 **1 条主效果**（`effect_ids` 的第一条，释放路径按它走）与 **1 份自身增益**
   （`buff_ids`，只有增益类能配）；而**命中才挂的敌方状态**写在**效果行的 `buff_id`** 上。
   两条路别混——"挂着谁"是两件不同的事。

## 1. 三层结构与"逻辑"的完整词汇表

改技能之前先看这一节：**下面列出的每一项都是代码里真的有消费点的**。不在表里的取值，
要么不存在，要么是"配置上写了、战斗里没人读"的静默失效（本工程明确不做这件事）。

### 1.1 Skill 层：释放控制（`SwordSkill.csv`，17 列）

| 字段 | 取值 | 它决定什么 |
| --- | --- | --- |
| `kind` | `projectile` / `target` / `ground` / `buff` / `summon` | **派发键**：这一式是怎么放出去的（也决定冷却怎么写、施放路径怎么走） |
| `cooldown` | > 0 | 冷却秒数；**神通**（`trigger_chance > 0`）时它是**最短触发间隔** |
| `range` | > 0 | 选敌距离，**同时是施放条件**——射程内无合法目标就**不空放、也不消耗冷却** |
| `realm_id` | `realm_0..4` | 境界（剑诀书序 = CSV 行序） |
| `max_level` / `cost` / `cost_growth` | — | 成长与价目：消耗 = `ceil(cost × cost_growth ^ 当前等级)` |
| `trigger_chance` | 0～1 | `0` = 冷却到点自动放；`> 0` = **神通**，改为普攻出手时按概率触发 |
| `trigger_chance_step` | ≥ 0 | 未触发时逐次累加的概率（**当前全表为 0**，机制保留） |
| `targeting` | `nearest` / `highest_hp` / `lowest_hp` / `farthest` / 空 | 选敌方式，见 §2.3 |
| `hits` | `ground` / `air` / `both` / 空 | 能打到哪一层，见 §2.3 |
| `cast_root` | ≥ 0 | **施放瞬间的全屏定身秒数**（不看射程，裂隙除外） |
| `effect_ids` | `\|` 分隔 | 引用 `SkillEffect`，**第一条是主效果**；增益类必须为空 |
| `buff_ids` | `\|` 分隔 | 施放瞬间无条件施加的**自身增益**；只有增益类能配，且**恰好 1 个** |
| `description` | 文本 | 给玩家看的说明（本文逐条抄录） |

### 1.2 Effect 层：瞬时行为（`SkillEffect.csv`，28 列）

**四种 `effect_type`（每种只有一个调用点，派发是穷举的）**

| 取值 | 是什么 | 参数来自 | 当前载体 |
| --- | --- | --- | --- |
| `attack` | 释放路径的那一次出手 | 效果行自己的形态与编排列 | 12 式伤害型法术 |
| `auto_attack` | **定时自己出手**的一次攻击 | 自带 `power` + `range`，**不吃技能成长**、不写冷却 | `e_guard` 环绕飞剑 |
| `shorten_cooldown` | 缩短一个随机法术的冷却 | **纯派发标记**，本身无参数 | `e_shorten_cd`（由 `on_crit` 触发） |
| `mirror_cast` | 影分身复制 | **纯派发标记**，本身无参数 | `e_mirror_cast`（由 `on_skill_cast` 触发） |

**命中时的条件型倍率（`condition`，进 DMG3 的 Build 乘区）**

| 取值 | 含义 | 当前载体 |
| --- | --- | --- |
| 空 | 无 | 多数法术 |
| `target_hp_below` | 斩杀：目标气血比例低于 `condition_value` 时**伤害翻倍** | 17 天剑（0.3） |
| `target_has_state` | 利用状态：目标带着**任意状态**时伤害 ×(1 + `condition_value`) | 10 斩鬼神（0.3） |

**飞行形态（`trajectory`）**

| 取值 | 行为 | 当前载体 |
| --- | --- | --- |
| 空 / `bolt` | 直线追踪单体 | 寒冰龙卷（`ground`）、定点类 |
| `line_shot` | 肩侧平射、不追踪，命中**最先遇到**的敌人即散 | 01 御剑术 |
| `line_pierce` | 身前贯穿，沿途每个敌人各结算一次 | 17 天剑、05 剑气流云壁 |
| `sky_drop` | 目标上空**固定剑阵**垂直落剑，X 冻结不追踪，落地按半径结算 | 06 万剑决、02 焚天剑诀、18 苍穹剑陨、15 诛仙剑阵 |
| `arc_homing` | 弧线追踪，弧度在 `arc_min`～`arc_max` 间随机（可为负 = 从下方掠过） | 11 青元剑芒 |
| `hover_homing` | 头顶悬浮后追踪 | **无**（词汇保留） |

**编排与命中旋钮**（正交，可自由组合）

| 字段 | 作用 |
| --- | --- |
| `projectile_count` | 单次出手弹数 |
| `hover_time` / `volley_interval` / `volley_jitter` | 起飞前停留（蓄势 / 浮现 / 下坠停留）与多发错时 |
| `speed` | 弹速（0 = 默认 1500，只作用于法术） |
| `spread` | 弹群间距；`sky_drop` 为落点横向间距（**参与判定**），**只在多弹时有意义** |
| `band` | `sky_drop` 的**黑洞铺开宽度**（各锁一敌编排，见 §2.4） |
| `spawn_jitter` | 出生高度抖动（仅表现） |
| `pierce_chance` | `line_shot` 首次命中的概率穿透（**一次判定机会**） |
| `aoe_radius` | 范围半径；`ground` 为 0 回退 220，`sky_drop` 必须为正 |
| `aoe_all` | 1 = 落地 / 范围结算**命中全场**（`aoe_radius` 退为表现用） |
| `knockback` | 每次命中**背离玩家**推开距离（裂隙永不移动） |
| `gather` | 每次命中朝**本效果中心**拉近距离（取 `min`，收敛到中心即停） |
| `duration` / `delay` / `tick_interval` | 下坠时长 / 定点前摇 / 周期结算间隔（`ground` 与天降火海必须为正） |
| `power` / `skill_flat` | DMG1 的 `SkillRate` 与固定伤害项（**`skill_flat` 当前全表为 0 = 尚未投放**） |
| `range` | **只对 `auto_attack` 有意义**（必须为正，否则永远够不着） |
| `buff_id` | 命中时挂哪份状态（在加载期解析成 `BuffDef`） |

### 1.3 Buff 层：时间化行为（`SkillBuff.csv`，9 列）

`kind` 共 **11 种**，`target` 必须与 `kind` 方向一致（加载期拦）。同一个 kind 再挂一次是
**刷新覆盖，不是叠加**（V1 没有叠层）。

| `kind` | `target` | `value` 的含义 | 当前载体 |
| --- | --- | --- | --- |
| `dot` | enemy | 每秒伤害倍率 | `buff_burn` 灼烧（焚天火海） |
| `chill` | enemy | 减速比例（额外记一份状态供表现层染冰蓝） | `buff_chill` 寒冷（寒冰龙卷） |
| `stun` | enemy | 无强度，只看 `duration` | `buff_stun` 麻痹（御雷真诀） |
| `slow` | enemy | 减速比例 | **无** |
| `vulnerable` | enemy | 增伤比例 | **无**（已下线，将来由剑意授予） |
| `haste` | self | 冷却流逝加快比例 | `buff_haste`（仙风云体术） |
| `crit_reduce` | self | 暴击率**绝对**加成；`extra` = 暴击缩短的冷却秒数 | `buff_crit`（醉仙望月步） |
| `shield` | self | 护盾 = 攻击 × value | `buff_shield`（剑罡护体） |
| `mirror` | self | 继承比例（0～1 的小数） | `buff_mirror`（剑二十三） |
| `regen` | self | 每秒回血比例（占气血上限） | **无** |
| `lifesteal` | self | 吸血比例 | **无** |

额外两列：`damage_window`（判据）/ `damage_window_power`（量）——**声明了才写一格共享伤害倍率窗**，
**当前 15 式没有一个声明它**（历史载体是退役的「护心剑罡」）。

### 1.4 时间轴与事件触发器（Buff 怎么把 Effect 再叫起来）

| 表 | 白名单 | 语义 | 当前在役 |
| --- | --- | --- | --- |
| `SkillBuffTimeline.csv` | `on_tick` | 到点（`interval` 秒）执行一次 Effect | `buff_shield → e_guard`，0.8 秒 |
| `SkillBuffTrigger.csv` | `on_crit` | 战斗里**暴击**时执行一次 Effect | `buff_crit → e_shorten_cd` |
| | `on_skill_cast` | 本体**释放法术**时执行一次 Effect | `buff_mirror → e_mirror_cast` |

> `on_hit` / `on_kill` / `on_damage` / `on_enemy_death` **不在白名单**——它们要等
> [../design/combat.md](../design/combat.md) §8 的事件总线上线。**白名单只放已经有消费点的取值**：
> 提前放进去就是"配置上写了、战斗里没人读、还不报错"的永不执行分支。

## 2. 技能之外的框架逻辑（技能会接上、但不在技能配置里）

这一节是"改技能时必须知道的既有规则"，全部已在代码里生效。

### 2.1 出手与结算

- **出手快照**：暴击判定**全游戏只有一处**（`Launch`），逐弹丸各摇一次；摇中的结果与"这一刻的共享
  伤害倍率窗"一起写进效果，此后由它派生的一切结算（同一弹丸的其余命中、地面场每跳、天降落点、
  灼烧每跳）**共享这份快照、不重新摇**。
- **伤害公式**：`DMG1 = 最终攻击 × SkillRate + skill_flat` → `× 通用增伤 × 暴击 × Build × 易伤`。
  `SkillRate = 效果行 power × (1 + 技能等级加成 + 参悟加成)`，技能等级加成走
  `game_settings.skill_level_bonus`（0.15）。
- **Build 乘区（攻击者侧、带条件）**：共享倍率窗 × 斩杀 × 利用状态。**目标侧修正（易伤）按落地那一刻算**，
  不吃出手快照。
- **伤害统计归因**：按技能 id 记账；空串 = 普通攻击；灼烧跳伤归到**施加它的那个技能**；
  **影分身那一份归到剑二十三**（复制出来的伤害算剑二十三自己的价值）。

### 2.2 频率（冷却与攻速）

- **冷却流逝只有一个衰减点**：普攻键吃 `attack_speed`，输出类法术 / 神通 / 剑灵吃 `skill_cdr`，
  **增益类法术两样都不吃**（否则增益会在自己持续期内转好，变成常驻）。
- `haste` 同时给**普攻速度与法术 CDR**（它的文案就是"出手快如疾风"）。
- **增益类法术的升级长在覆盖率上**：实际冷却 = `max(持续 × buff_cooldown_floor_ratio(1.25),
  冷却 × (1 − buff_cooldown_per_level(0.02) × (等级−1)))`——峰值强度不变，覆盖率封顶 80%。
- **神通**：冷却未就绪不摇概率；神通**不进**"暴击缩冷却"的候选池。
- **暴击缩冷却的两条护栏**：候选只从"已习得、冷却 > 0、非增益类、非神通"里抽；
  **每次施法最多触发一次**（由该次施法的第一支弹丸负责）；扣减后的冷却**不得低于
  `该法术冷却 ÷ (1 + skill_cdr 上限)`**（按秒扣与 CDR 的除法必须服从同一条上限）。

### 2.3 选敌与层

- **`targeting`**：空 / `nearest` = 最近的合法目标（受 `range` 限制）；`highest_hp` = **全场血量最高者、
  无视射程**；`lowest_hp` = **射程内**血量最低者；`farthest` = 射程内**最靠前**的那只。
  多发按对应顺序取前 n 个，**敌人不足时循环重复打同一个**（场上只有一只时几段全打在它身上）。
- **`hits` × `monster.layer`** 必须配对才结算，三处收口（选敌 / 命中结算 / 范围扫描）。
  空 / `both` 打两层；`ground` 只打地面；`air` 只打空中（**当前无使用者**）。
  **`hits` 与 `kind` 是两件事**：寒冰龙卷 `kind = ground`（落在地上的力场），`hits` 留空，照样打得到空中。

### 2.4 命中之后

- **击退**：`e.X += sign(e.X − 玩家X) × knockback`，背离玩家推开；**死在这次伤害上的目标不再移动**
  （免得尸体滑动）；**裂隙永不移动**。
- **吸附**：`e.X += sign(效果中心X − e.X) × min(gather, |效果中心X − e.X|)`——"效果中心"就是
  `CombatEffect.X`；**取 `min` 所以收敛到中心就停**，不会来回弹。速率 = `gather ÷ 结算间隔`。
  **不要与 `knockback` 同配**（自检有一条断言锁住）。
- **各锁一敌（`band > 0` 的 `sky_drop`）**：每支各锁一个（尽量不同的）目标、落在它当时的位置爆炸；
  天上的黑洞以**目标群的中轴**为心铺开 `band` 宽并夹进画面。锚在**目标**上而不是角色上
  （角色每秒走 340，锚在角色上落点会甩到身后）。落地派生一个 `Damage = 0` 的 `ground` 余韵
  （0.3 秒）供表现层画爆炸，它**一次结算都不会走到**。
- **目标中途死亡的补救**：追踪弹（`hover_homing` / `arc_homing`）**先飞完这一程**到目标最后的位置，
  再在 80 单位内挑**血量最低**的敌人接着追、**弧度取反**，最多改索 2 次；
  定点弹（`target`）直接在落点 80 单位内挑血量最低的**当场结算**。**索不到敌就消散，本次伤害丢失**（有意）。
- **天降火海**：`sky_drop` 且效果行 `buff_id` 指向一份 `dot` 时，落地**不做一次性结算**，
  改为在落点留下一片寿命 = 那份 `dot` 时长的 `ground` 火海，每 `tick_interval` 秒对范围内全体结算一次
  **并刷新灼烧**（不是叠加）。与 `aoe_all` 互斥（加载期拦）。
- **层不匹配直接不结算**：`Hit` 里 `LayerHit` 是"飞行单位免疫地面技能"的最后一道防线。

### 2.5 击杀、奖励与解锁（技能打出来的后果）

- 击杀掉 `monster.gold + 天赋 drop_flat`（**裂隙不加**，也**不加** `drop.csv` 的奖励组）。
- 首次击杀普通怪 → 解锁「修行」系统。
- BOSS 首杀 → 按 `level.first_reward` / `repeat_reward` 发奖；**灵核只在首杀发 1 个**，
  与首杀账本作为**同一次存档提交**。
- 裂隙被击破 → 通关。

## 3. 逐技能清单

> 每式按 **描述（配置原文）→ 实际效果 → 可触发的逻辑 → 备注** 展开。
> 「可触发的逻辑」= 它在运行时真的会走到的分支 / 会被哪些框架逻辑接管，不是设计意图。
> 数值都是**草案初值**；`power` 一律是**每支**的威力，单次施法总量 ≈ `power × 命中数`。

### 炼气（`realm_0`）· 入门：直伤点杀 + 攻速 + 收割

---

#### 01 御剑术 · `skill_01`（弹道）

| 项 | 值 |
| --- | --- |
| 描述 | 剑诀御剑，飞剑自肩侧横射而出，击中即散。 |
| 冷却 / 射程 | 1.2s / 950 |
| 效果 | `e_01_sword`：`attack`，`power 3.5`，`line_shot` ×1，前摇 0.12s，速度 1500 |
| 自身增益 | 无 |
| 状态 / 条件 | 无 |

**实际效果**：出手当拍全游戏**唯一的弹道结算点**之一，沿直线平射、**命中路径上最先遇到的那只即结算并销毁**；
`pierce_chance = 0`，所以不穿透。`power 3.5` 是**刻度锚**——"1 支 = 1 SU"（1 SU = 该关标准怪 HP）。

**可触发的逻辑**：
- 冷却到点**自动释放**（非神通）；射程内无合法目标 → 不空放、不消耗冷却。
- 走 `attack` 出手路径 → 走**出手快照**（摇暴击、定格倍率窗），进伤害统计（来源 `skill_01`）。
- **是"暴击缩冷却"的候选**（若 `buff_crit` 在役）。
- **会被影分身复制**（若 `buff_mirror` 在役）：复制那一支从分身处（身后 110）出发、晚 0.18s。
- 命中不挂任何状态、不吃任何条件乘区。
- `line_shot` 在**起飞前停留期间跟着施法者走**（前摇里角色还在前进）。

**备注**：玩家**开局不附带**它，要在技能页花 30 灵石点「习得」。剑支数（1 → 5）是它的成长轴，

- 触发点还有三条"什么时候允许触发"的护栏：普攻（skill 空）不算、**影分身那一份不算**、派生结算不算。
- 它给的是**乘区收益**（让全队暴击一起变多），是"境界 4 的效率台阶不必靠 `power` 等比膨胀"的那条轴。
- 增益类不吃攻速 / CDR；升级只提覆盖率。

#### 19 剑二十三 · `skill_19`（增益 · 影分身）

| 项 | 值 |
| --- | --- |
| 描述 | 天光骤暗，身后凝出一道影分身，随本体同放剑诀，只是力道稍逊。 |
| 冷却 / 射程 | **40s** / 950 |
| 效果 | **无瞬时效果** |
| 自身增益 | `buff_mirror`：`mirror` / self / 10s / value **0.7** |
| 事件触发器 | `tr_skill_mirror`：`buff_mirror` 的 `on_skill_cast` → `e_mirror_cast`（`mirror_cast`） |

**实际效果**：**化神档唯一的乘区**。10 秒内，本体**每释放一个法术**，身后的半透明分身就同步再放一份，
伤害按继承比例打折（默认 0.7）。施加时照例回 5% 气血。

**可触发的逻辑**：
- 继承比例 = `value(0.7) + 0.01 × (技能等级 − 1) + 参悟加成`，**不封顶**——全游戏最陡的一条后期成长轴。
  所以剑二十三那 4 行 `SwordUpgrade` 的 `value` 填 **0.01**（其他技能 0.08），两条轴才是同一个「每级 +1%」。
- 镜像走**"发出一式"而不是"释放这一式"**——它复用出手路径（`ExecuteEffect → CastVolley → Launch`），
  而**不是**重新走一遍 `Release`：所以**不写冷却**（不会多发一次释放音）、**不重复结算 `cast_root`**。
- **跳过增益类与召唤类**，并**跳过影分身自身**（递归不可能发生）。
- 弹道类从**分身**的位置出发（身后 110），**起飞前停留期间也跟分身走**；
  分身那一式**晚 0.18 秒**出现（`target` / `ground` / `sky_drop` 三类没有发射点，全靠这一拍读出来）。
- `CombatEffect.Mirrored` 让表现层不挂第二次技能名标签，也让**分身出手不替本体缩冷却**。
- **伤害归到剑二十三**（不藏在被复制的那一式里）。
- 已知取舍：镜像的 `dot` 火海会把本体的灼烧刷新成较弱的那份；`knockback` 会翻倍。
- 增益类不吃攻速 / CDR，所以 25% 的覆盖率是稳定的。

**备注**：不封顶带来的平衡风险记在 balance_ttk.md 第 9 节（待复核）。

## 5. 当前**没有在役载体**的配置项（零件箱）

这些取值在代码、校验与自检里**都有完整覆盖**，但**当前 15 式一个都没用**。
要用它们**不需要写新代码**——加一行配置即可，这也是"扩展技能"最便宜的一条路。

| 缺载体的取值 | 在哪一层 | 说明 |
| --- | --- | --- |
| `buff kind = slow` | Buff | 与 `chill` 同源的纯减速（不带"受寒气所侵"那层状态） |
| `buff kind = vulnerable` | Buff | 易伤（+X% 受创）；已下线，计划由**剑意**授予某个技能分支 |
| `buff kind = regen` | Buff | 每秒回血（占气血上限比例） |
| `buff kind = lifesteal` | Buff | 吸血；退役库里 `r_b_lifesteal` 是活样例行 |
| `trajectory = hover_homing` | Effect | 头顶悬浮后追踪 |
| `hits = air` | Skill | 只打空中 |
| `kind = summon` | Skill | 跟随召唤（脚本身后、每秒发一枚弹丸）；机制留给以后的剑灵系统 |
| `trigger_chance_step > 0` | Skill | 神通概率逐次累加（曾用于寒冰龙卷，现全为 0） |
| `damage_window` / `damage_window_power` | Buff | 共享伤害倍率窗；历史载体是退役的「护心剑罡」 |
| `skill_flat > 0` | Effect | DMG1 的固定伤害项（**唯一不随境界缩放的项**，用前想清楚） |
| `trigger_type = on_hit / on_kill / on_damage / on_enemy_death` | 触发器 | **代码里还没有消费点**（等 combat.md §8 的事件总线），**不是零件，是缺口** |

> **退役库**（`*_Retired.csv`，不参与加载，同 schema 同解析器）是"以后可复用的机制库"：
> 三个 `summon`、三个 `ground` 剑阵、`pierce` / `multi` / 斩杀召唤等都在里面。
> 自检会**用同一套解析器读通退役库**，防止它与在役表悄悄分叉。

## 6. 改技能时的检查清单（给 AI 的硬约束）

### 6.1 加载期（`SkillTable.Parse` / `GameConfig`）会**直接拒绝**的写法

- `power` ≤ 0 的 `attack` / `auto_attack`（放了等于没放）；`auto_attack` 没有正的 `range`。
- 增益类：`buff_ids` 必须恰好 1 个，`effect_ids` 必须为空。
- 非增益类：`buff_ids` 必须为空（命中才挂的状态写在**效果行的 `buff_id`**）。
- 非 `projectile` 类不许有自定义 `trajectory` 与多弹（`projectile_count`）。
- 只有 `ground` 力场与天降火海能配 `tick_interval`，且 `ground` 必须为正。
- 非增益类主效果的 `delay + duration` 不能都为 0（否则出生当帧被回收）。
- `sky_drop` 必须有正的 `aoe_radius`；`band` 只对 `sky_drop` 有意义且 ≤ 1400；
  天降火海（`sky_drop` + `dot`）与 `aoe_all` 互斥。
- `mirror` 的 `value` ≤ 1；`damage_window = 0` 时 `damage_window_power` 必须为 0，
  声明了则必须为正且 **≠ 1**。
- `shorten_cooldown` / `mirror_cast` 是**纯派发标记**：逐列检查，**每一列都必须是默认值**。
- `condition` 与 `condition_value` 要么都空 / 0，要么都有值（0 就是一行死配置）。
- 白名单：`effect_type` / `condition` / `buff kind` / `target` / `trajectory` / `targeting` / `hits` /
  时间轴 `trigger` / 触发器 `trigger_type` —— **新增取值必须同时补 handler 与 `SkillText` 文案**，
  否则要么加载期拦、要么运行时抛错。

### 6.2 自检（`tests/IdleSword.Checks`）会拦的护栏

- 每境恰好 3 个法术、境界内的 id 集合固定（改编制要同步这条断言）。
- **每个法术的 `range` 都不短于预览靶距 520**（射程比靶距短 ⇒ 预览页什么都演示不出来）。
- **`knockback` 与 `gather` 不同配**（反向、会互相抵消）。
- `band` 只对 `sky_drop` 有意义、且 ≤ 1400。
- 天降余韵（`Damage = 0` 的 `ground`）**不造成任何伤害**。
- 影分身：不递归、伤害打折、从身后出发、晚一拍、窗口过期后不再产生镜像。
- **文案里不许出现配置里的原始枚举值**（`SkillText` 是穷举 + 抛错，漏一个取值当场炸）。
- 派生视图逐字段等于拆分前的值（搬家没改语义）。

### 6.3 改完必须做

```powershell
dotnet run --project tests/IdleSword.Checks.csproj -- idle-sword/Config/Tables
```

- **动任何数值之前**先读 [../design/balance_ttk.md](../design/balance_ttk.md)（境界对齐三步走）
  与 [../design/skill_values.md](../design/skill_values.md)（水位口径）。
- **改伤害公式**要用 git worktree 在 HEAD 开基线、`--sample` 逐字节对比
  （别信代数推导，本工程吃过一次 4.9% 的静默漂移）。
- **改 UI** 之后编译并跑 Godot `--smoke-test`，布局变更用 `--capture` 看实际画面。
- 改配置字段要**同步** `docs/data/fields.md` 的字段字典与加载期校验。
