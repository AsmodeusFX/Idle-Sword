# 工程框架方案

状态：框架原型已实现。现行文件组织与取舍见 `../planning/phase_01.md`，以下保留长期模块划分方向。

## 工程位置

沿用 `idle-sword/project.godot`，不另建平行工程。已实测 Godot 4.7 stable .NET（引擎版本串 `4.7.stable.mono`）+ .NET 10；当前选择 Compatibility 渲染器，程序集为 Idle-Sword。

## 模块职责

- 配置层：CSV 解析、类型转换、交叉引用与范围校验，形成只读配置对象。
- 战斗层：目标筛选、独立技能冷却、效果执行、伤害与死亡结算。合法目标可包括敌人、自己、友方或有效位置，由技能类型定义。
- 关卡层：维护连续世界位置、刷怪点状态、格号、BOSS 状态与传送条件。
- 养成层：校验条件、统一扣费、更新永久进度并重算属性。UI 不直接操作货币或最终属性。
- 表现层：根据状态播放动画、特效、背景滚动、数字提示与音频；特效数量不改变伤害。音频（BGM 与音效）归属表现层，触发点从公开状态推导，素材映射见 `Assets/audio.json`，生成器见 `tools/SoundGen/`；像素精灵的映射见 `Assets/visuals.json`、生成器见 `tools/SpriteGen/`（字符网格 + 调色板 → 64×64 SVG，带 `--verify` 回读校验），表现层的挤压拉伸、扬尘与受击白闪都在 `BattleView` 里，不写回任何玩法状态；同一音效的高频重复由音频层统一按最短重触发间隔与音高抖动抑制，不靠调用点各自去重。召唤物与跟随单位的**站位**同样属于表现层（`BattleView.FollowerSlot`），由表现层分配位次决定。
- 存档层：保存版本化玩家数据、首杀/首通记录、库存与未收取产物。运行时战斗状态与永久进度分开建模。应用设置（画面、音量）另存 `user://settings.json`，与进度分文件：重置进度不得连带清掉显示与音频偏好，且设置损坏时回落默认值继续启动而非拒绝加载。

## 必须避免的结构错误

- 不把推进写成“清怪后格号加一并瞬移”；连续移动与刷怪计时同时工作。
- 不因玩家离开参悟页面销毁参悟生产逻辑；页面只观察持久系统状态。
- 不因裂隙属于怪物表而把它算进“解锁裂隙前必须消灭的怪物”集合，避免永远不可攻击。
- 不在 BOSS 已死后继续由旧定时器生成小怪。
- 不把 BOSS 格复活复用成普通格全关重置。
- 首次奖励、死亡事件、传送事件必须防止重复结算；循环关卡有独立的本轮遭遇状态。
- 每关 BOSS 首杀奖励固定为 1 个灵核，首杀账本使用稳定关卡 ID；首杀标记与奖励入账作为同一次持久化变更保存，不能由两个独立保存步骤完成。
- 灵核入账只通过首杀结算入口，通用可重复掉落不能绕过该约束。累计投放与可消耗余额分开记录。
- 不在 `_Ready` 等 Godot 回调里靠抛异常报错：Godot 会把 C# 异常转成控制台错误并继续运行，异常既不会中断进程也不会让 `--smoke-test` 失败，结果是“资源没导入但自检照样通过”。资源缺失必须显式记录（`BattleView.LoadError`）并由启动流程提示、由自检断言。
- 表现层只读模拟状态：命中反馈、飘字、状态图标由表现层自行从血条差分与 `EnemyState` 公开字段推导，不为了特效往 `Core/` 里回写仅供显示的状态。**击杀与技能释放同理**：击杀由"敌人从列表消失"推导（死亡敌人已在同一次 Step 里被移除），技能释放由"冷却 0 → 正"的跳变推导，不为音效给 `GameSession` 加死亡事件或击杀计数。
- 切关清理旧目标、弹丸、持续区域及召唤物的归属，避免旧效果影响新关。
- 不为"让召唤物错开"去改 `Core/` 里那个把召唤物 `X` 钉在玩家身后的锚点：站位是表现，锚点只是绘制基准。同理，灼烧跳伤的识别属于表现层的血量差分，不要为了少播一个音就禁止 DoT 在 Core 里逐跳结算伤害。
- 表现层的判据不要拿 `_Process` 的真实帧间隔当"经过了多少游戏时间"：模拟按固定步长推进，一帧可能跑 0 个也可能跑很多个步，真实帧间隔与模拟时长不成比例。需要时间量时读 `GameSession.Elapsed` 的差值。
- 不要在 `RefreshSettings` 这类"把设置回填到控件"的路径里给 `ButtonPressed` 赋值：它的 setter 会发出 `Toggled`，于是"打开设置面板"会反过来触发一次应用显示设置并落盘。回填一律用 `SetPressedNoSignal`。
- 退出最大化/全屏后不要在同一帧设窗口尺寸：操作系统会异步把窗口还原成进入之前的尺寸并盖掉这次设置。推迟一帧再套用。
- 显示设置要落到真实窗口并接受真实控件的信号验证。只断言配置文件里的数值，会把"界面改了但窗口没动"整类问题放过去。
- 打包不要只看 Godot 的退出码：`--export-release` 在导出失败时同样返回 0（godot#85062），只盯退出码会把坏包放过去。必须断言产物本身（exe 体积、不得出现外置 `.pck` 或 `data_*` 目录），再让打出来的 exe 拷到仓库外自己跑一遍。
- 工程不能缺少 `Idle-Sword.sln`：Godot 的 .NET 导出靠它判断工程是否含 C# 代码，缺了它导出会**卡住不收尾**——留下一个 `*.tmp`，既不产出 exe 也不报错退出。该文件必须入库。
- 安装导出模板（`.tpz`）时要剥掉归档里的 `templates/` 前缀：引擎找的是 `<版本目录>/windows_release_x86_64.exe`，整包原样解压会深一层，导出时报找不到模板。版本目录名由引擎版本串去掉最后两段得到（`4.7.stable.mono.official.<hash>` → `4.7.stable.mono`）。
- 不把美术尺寸当作逻辑攻击距离。

## 规范

- C# 类型、公开成员和文件使用 PascalCase；CSV 字段使用 snake_case，指定 CSV 文件名保留原大小写。
- 模块职责、公开接口、公式、状态转换和非显然约束写中文注释。
- 集中定义数值单位、属性叠加与数值表示，保留大数值扩展空间。
- 发行打包固定为一条命令 `tools/PackWindows.ps1`，不引入第三方打包工具：Godot 官方的 `--export-release` 已经覆盖导出本身，外面的封装（Docker 镜像、各类 CI action、安装器）都只是它的薄壳，接进来只会多一层引擎版本对齐的负担。脚本负责官方命令没有的那部分——前置检查、模板安装、产物断言与独立运行验证。
- 交付物是**单文件 exe**：`binary_format/embed_pck=true` 与 `dotnet/embed_build_outputs=true` 同时生效，引擎、PCK、C# 程序集都在同一个文件里，不存在"exe 与 pck 分家"的失败模式。
- `tools/` 下的 PowerShell 脚本必须存成**带 BOM 的 UTF-8**：Windows PowerShell 5.1 不认识无 BOM 的 UTF-8，会把中文注释按 GBK 双字节解析，吞掉后面的引号与括号，报一堆莫名其妙的"缺少右括号"。
- 文档、配置源表和代码进入版本控制；引擎缓存与构建产物不提交。
- 配置写入通过开发工具完成；玩家运行进度保存到 `user://`，不覆盖配置源表。

## 后续关键验证

- 移动途中计时到点仍生成怪物；越过点后不再生成，已生成怪物仍存在。
- 未进入的格不提前生成怪物；攻击距离外存在怪物时可继续走，进入攻击距离时停下。
- 普通格死亡回关卡起点；BOSS 格死亡不重新激活前面的刷怪点。
- BOSS 格复活后角色满血，敌人保留剩余 HP，已死亡 BOSS 不复活；BOSS 已死时不恢复小怪刷新。
- BOSS 死后停止刷新；剩余怪物清空才使裂隙成为合法目标。
- 裂隙击碎与最后敌人死亡同帧时只传送一次。
- 首杀奖励不会因复活、循环或加载重复领取。
- 同一关首次击杀得到 1 个灵核，重复击杀得到 0 个；不同关卡共用 BOSS 模板时各自首次发放 1 个。
- 杀死 BOSS 后尚未击碎裂隙就死亡或退出，不重复发放首杀奖励；消耗灵核不恢复首杀资格。
- 所有关卡首杀完成后，累计灵核投放恰好等于关卡数；通用掉落及其他产出配置不能增加投放。
- 参悟页面关闭与切换不影响在线产出；鼠标扫过合并产物只结算一次。
