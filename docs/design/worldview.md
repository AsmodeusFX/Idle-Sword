## 二、为什么修仙（基调）

> 没有雷劈，没有点化，没有奇遇。
> 你就是醒了。你觉得自己该去修仙，于是你就去了。

- **基调**：魔性、轻、可爱；外面套一层修仙的壳。内核是"越打越强、越打越怪"的爽感。
- **终极目标**：修成**土豆天尊**。土豆天尊是什么？**不解释**。你修到了，你就是。
- **主角**：一颗**椭圆形的白色土豆**（参考《土豆兄弟》最初那个造型），**开局就背着剑直接出发**。
- **关键取向：弱化"剑修"**。主角不是剑修，是**一颗修行的土豆**。**剑是它捡到的法宝**，不是它的道——
  这条决定了所有命名该读作"**精怪的本事**"，而不是"剑法"。

## 三、关卡包装参考（**后期可用，当前不改关卡结构**）

> ⚠️ **这一节是素材库，不是决定。**
>
> 用户明确：下面这套"一层层往上打"是 **AI 给的关卡包装参考**，先记下来后期可能用。
> **当前的关卡运行结构一行都不动**——`level.csv` 的 100 关、每关 25 格、连续移动、进格激活刷怪、
> 越过刷怪点停刷、每 20 关解锁一档境界，全部照旧。这一节不构成任何实现要求。

**参考设定**：世界是一层层的，从最底层的荒野到最高层的天界；每层有多个小关，小关尽头是守关 BOSS。

   现有的**五档境界**（`小妖 / 妖将 / 妖王 / 妖尊 / 妖圣`，见 `SwordLevel.csv`）与 15 个法术的分组

2. **"层"不引入新的运行概念**。层是包装层的分区说法，**不是**新的修行等级，也**不是**新的关卡机制。

**如果将来真要采用**：优先做的是**换皮**——把 `level.csv` 的关卡名与 `monster.csv` 的怪物名/形象
按层重刷一遍，让"越打越高"在画面上看得见；**这是内容替换，不是机制改动**。
（现有关卡名是「青岚山麓 / 听泉竹径 / … / 天门·N」；现有怪物模板 10 个：

> 顺带一提：这套参考里"每层尽头一个守关 BOSS"的读法，跟现在 `时空裂隙`（关卡出口，打碎即传送）的

## 四、序章与 BOSS 对白

### 1. 序章片段 —— **已实现**

小土豆**开局就背着剑**从天上落下来 → 落定 → 一路向右走 → 走到画面右半边**画面渐黑** → 切到第一关。

**用户后来简化过需求**：不做捡剑动画、不做悬浮气泡与叹号——剑一开始就在背上。

**镜头约定**：序章**镜头不跟随**（土豆落在画面中间、自己在画面里走，背景不滚）；
切到第一关时画面**快速渐亮**，土豆带一段**从左边走进来的位移**。

> 实现落在 [UI/Prologue.cs](../../idle-sword/UI/Prologue.cs)，**只在全新存档时播一次**；
> 开发与截图可以用 `--prologue` 强制播放。做法上它**不推进 GameSession**（详见 `phase_01.md` 的交付记录）。

## 八、15 个法术（已定，已落地）

**命名原则**：读作"精怪的本事"而不是"剑法"；能用土豆/精怪自己的东西命名就优先用它（护盾 = **薯皮**）；
词库里保留少量"剑"（法宝本身 + 几个确属剑形的招式）；不用能被认出出处的词。

御剑 / 疾风 / 须芒 / 万剑 / 天剑 / 薯皮 / 妖火 / 扎根 / 落雷 / 天陨 / 望月 / 寒潮 / 身外身 / 斩鬼 / 诛仙。

> 已回填到 `SwordSkill.csv` 的 `name` 列与 [sword_skills.md](sword_skills.md)。

## 十、不受世界观影响的底座（换了名字也不用重做）

- **机制层已定的东西**不随命名变：参悟的四个**形状**（少档大步 / 中档 / 多档小步 / 开关式）、
  **分类与上限分离**、**60 格表结构**（15 法术 × 4 档）。
- **已落地的代码地基**照常有效：`SkillBonus` 按 `effect` 分类、`SaveStore` 不再拒绝超过等级上限的等级。
- **逐技能拓展清单**（[sword_intent.md](sword_intent.md) 第二节）描述的是**行为不是词**，可以直接搬进新包装。
- **美术侧**：`tools/SpriteGen` 的字符网格与全族调色板（见 [../art/asset_spec.md](../art/asset_spec.md)）——
  改怪物名不动美术，改怪物形象才动 `Monsters.cs`。
