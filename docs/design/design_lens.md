# 设计镜片：养成系统的三层流转

> 状态：**工作口径，不是铁律**。这是 Ver2.0 开局时用户给的一套思考方式，用来支撑设计决策；过程中会迭代，也可能被推翻。
> 与 `intent_packaging.md`（**2026-10-09 随参悟删除**，Git 历史可查）的既有口径（「养成系统本身不麻烦，麻烦的是包装」）是同一类东西：都是**先想清楚再动手**的工具，不是需求。

---

## 一、三层流转

任何一个养成系统，都可以拆成一次流转：

```
如何获取资源  →  如何消耗资源  →  产出什么价值
```

设计的时候要问自己：**在这一次流转里，玩家是在哪个层级获得乐趣？**

- **乐趣在获取侧**：系统大致长成「给玩家几个农民，能产出不同的资源，玩家决策把农民派到哪里去」。
- **乐趣在消耗侧**：比如天赋树——**选择加点方向本身就是乐趣**。大部分增量放置游戏的乐趣都在这里。
- 提醒：**「乐趣」不只有决策这一种**。随机 / 博彩同样能产生乐趣，所以别把「没得选」直接读成「不好玩」。

---

## 二、为什么增量游戏的乐趣偏向消耗侧

增量游戏的资源获取，大概率可以概括成"**随着时间递增**"——不管是掉落还是放置，都会跟时间绑定。获取侧的可操作空间因此有限，而**消耗侧可以做出很多花样**。

推论：**增量游戏的大部分系统都可以抽象成这个结构**（获取 → 消耗 → 价值），因为"获取"那一层已经被时间填满了。

---

## 三、但价值的根在第三步

回到最根上的问题：**玩家做决策的目的是什么？**

一定是他觉得这个交互**有价值**。也就是说——不管前两层做得多有趣，**如果第三步的价值落得不够，玩家就不买账，前面全白谈**。

而 RPG 游戏的价值怎么看待？**当然是战斗底盘中逐层释放出来的有效内容。**

### 由此得到的工序

> **先把战斗底盘梳理清楚，把构成战斗价值的内容分门别类梳理好，再分发给各个系统。**

顺序不能反：**投放价值的类型，也决定了用什么手段投放更合适。**

- 例：「御剑术的剑支数量 +1」与「攻击力 +1」这两个价值，在玩家层的吸引力完全不同——前者是形态变化（能看见、能数出来），后者是纯数值。对应的投放手段就该做出差异，而不是都塞进同一张加点表里。

所以 Ver2.0 里 **Part.2（巩固战斗底盘）是 Part.1（各养成系统结构）的前置**，尽管编号在前的是 Part.1。当前可投放的价值门类见 [value_inventory.md](value_inventory.md)。

---

## 四、可嵌套

好系统的设计，**不是只有这三层流转，而是可以反复嵌套使用这三层**。

即：某一层里的"产出什么价值"，本身可以是另一个完整的三层流转。判定一个系统设计得好不好，可以看它是不是在某个层级上又长出了一套自洽的「怎么产出 → 怎么花 → 给什么」。

---

## 五、怎么用（操作化）

设计 / 评估一个系统时，按这个顺序问：

1. **它的资源从哪来？**（是时间的函数，还是玩家的操作？）
2. **它把资源花在哪？**（玩家在这一层做的选择是什么？）
3. **它最终给玩家什么战斗价值？**（对照 [value_inventory.md](value_inventory.md) 的门类清单，说得出落点吗？）
4. **这份价值用什么手段投放更合适？**（形态类 vs 数值类，吸引力不一样）
5. **哪一层还能再嵌一套三层？**

**第 3 问答不上来的系统，先不要做。**
