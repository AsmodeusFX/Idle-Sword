# 核心规则

状态：已确认需求；可运行框架原型已实现，暂定细节见 `../planning/phase_01.md`。

> **下一步成长系统改造**：修行 / 法术 / 神通 / 神识的已确认目标框架见 [核心成长系统认知文档](core_growth_systems.md)。本文下述五系统及参悟等口径记录原型阶段；与新框架冲突的成长系统职责与边界以新框架为准。目标与现状的差异见其 §10，待裁定事项见 §11，不代表改造已经完成。

## 已确认：产品与范围

- 修仙题材横版增量放置游戏，参考《Zad Archery》的战斗与成长循环。
- 首发仅 Windows，使用 Godot .NET 和 C#。
- 1920×1080 设计尺寸，等比缩放；上半区战斗，下半区养成操作。
- 初期角色在地面行走。御剑系统留待后续，不属于当前五大系统。
- 当前五大系统为修行、境界/法术、铸造、参悟、剑灵；后续支持新增与长尾系统。
- 不做转生，不重置长期养成。
- 最小化继续挂机；退出游戏停止一切产出，无离线收益。

## 已确认：关卡与移动

- 初期配置 100 关，实际关卡数量由配置决定，可扩展。
- 每关长度一致，25 格，每格对应一屏逻辑距离；最后一格为 BOSS 格。
- 角色具有配置决定的移动速度，通常不随养成改变。
- 清空攻击距离内的怪物后，角色自行移动。不能用清怪后直接跳格代替移动。
- 攻击距离内出现合法怪物目标时停下，清空后继续移动；远处仍有怪物不阻止前进。
- 进入对应格时激活该格刷怪点，随后定时刷新；未进入的远处格不提前刷怪。
- 角色越过刷怪点后，该点才停止刷怪。走路时尚未越过的刷怪点仍可能刷新怪物。
- 波次间隔结束时，即使上一波未清空，仍叠加新怪。
- **一条波次混编多种怪**：刷什么由子表 `wave_unit.csv` 配置，`wave.csv` 管间隔、精英节奏与**波次强度系数**。当前六条波次分两档：第 1–50 关用「兽群 / 游猎 / 空袭」，第 51–100 关换代成「潮涌 / 猎阵 / 妖潮」。
- **每波的怪物数量随关卡递增，且递增本身在加快**（线性 + 平方两项），但每个模板都有一个**预设上限**，到顶就不再涨。数量与 HP/ATK 两段压力错开：数量先涨、第 100 关仍在增长，之后交给关卡倍率。
- **波次之间另有强弱梯度**：`wave.csv` 的 `hp_scale` / `atk_scale` 乘在关卡倍率之上，**只作用于普通怪**（精英 / BOSS / 裂隙是关卡节点，不随波次变硬）。
- 场上全部怪物清空时，可以继续前进。
- 手动返回旧关卡后，在选定关卡整关循环。
- 到达配置中的最后一关后，循环当前关。

## 已确认：BOSS 与裂隙

- BOSS 格出现 BOSS、怪物与时空裂隙。
- 裂隙使用 `monster.csv` 配置，是有 HP、不移动、不攻击的特殊怪物单位。
- 必须清空所有战斗怪物（包括 BOSS，不包括裂隙自身）才能攻击裂隙。
- BOSS 死亡后，小怪停止刷新。
- 清空战斗怪物并击碎裂隙后，才满足传送条件。
- 每关首次击杀 BOSS 时立即发放且仅发放 1 个灵核，重复击杀不给灵核；无需等到裂隙击碎或关卡通关。
- 首杀按稳定关卡 ID 记录，不按怪物模板 ID 记录；不同关卡复用同一 BOSS 模板时仍各有一次首杀。
- 灵核作为定量投放资源，当前五大系统不提供其他产出来源。累计投放量等于已完成 BOSS 首杀的关卡数，100 关最多投放 100 个；背包余额会因消耗而减少。
- 首次与重复奖励仍分开配置，重复奖励可以配置其他资源，但不能包含灵核。
- 例外：主界面 GM 按钮是开发调试通道（`GameSession.GrantAllCurrencies`），按 `item.csv` 中 `kind = currency` 的每一行各发一份，不属于五大玩法系统。它不写入首杀账本，因此「累计投放量 = 首杀关卡数」的口径仍以账本为准。

## 已确认：死亡

- **死亡行为各处一致**：不管死在哪一格（**包括 BOSS 格**），都**回当前关卡起点**复活，整关推进进度重置，不损失任何资源。
  - 早先 BOSS 格是"满血在本格安全位置重生、保留敌人伤势"（可以反复送死把 BOSS 磨掉）。**这条已取消**——用户要求死亡行为统一。
  - 直接后果：**BOSS 变成一道硬 DPS 墙**——打不过就是打不过，没有"磨过去"这条路。设计上这是有意的（打不过就回前面刷练度），但它是一处明显的难度台阶，见 [balance_ttk.md](balance_ttk.md) 第 5.2 节。
- **整关重置发生在复活读条归零那一刻，而不是死亡瞬间**：倒地演出期间怪与伤势都还在（表现上是"倒在杀死它的那堆怪中间"），也让 `PlayerX` 在倒地期间保持为死亡点、供倒地的镜头使用。
- **已领取的首杀奖励不因死亡、重试或整关循环而重置**：灵核记在玩家账本上。所以打死 BOSS 之后再死，关卡会重开、BOSS 会重新刷出来，但**首杀灵核保留**。

## 已确认：战斗

- 所有角色**法术**均为远程技能，涵盖子弹、定点目标、地面持续与 Buff 等类型（类别词汇里还保留召唤，但当前 15 个在役法术已没有召唤类技能）。**普通攻击是例外**：它开局是近战，见下。
- **剑二十三（影分身）不是召唤物**，是自身的短时状态：持续期内本体每放一个法术，身后的半透明分身就同步再放一份，伤害按继承比例打折。它没有血量、不吃仇恨、也不会被选中——「有血量、能被怪物选中」的实体召唤留给以后。
- 角色另有**普通攻击**：向最近的合法目标出手，伤害为「最终攻击 × `basic_power`」；没有合法目标时不空放、也不消耗间隔。间隔、倍率与射程都由 `fightattr.csv` 配置。
  - **有近战与远程两种形态**：**开局是近战**（挥剑斩击、射程 150、停步 120），在修行树上点亮**「剑气」**之后变为远程（平射飞剑、射程 950、停步 640）。近战不是换个画法——**射程与停步距离都真的缩短**，角色要走进去才够得着。
  - **伤害结算两条路共用一处**（`GameSession.TryBasicAttack`），手动与自动都走它，所以暴击、增益乘区与伤害统计不可能只覆盖其中一条。
- **普通攻击可以手动触发**：**点战斗区任意处**就挥一下。它与自动普攻**共用同一条判定与同一个冷却键**——点击只是"自己扣扳机"，**点快了就是白点**。冷却中刻意不给反馈（挥了却没伤害比没反应更像"游戏坏了"）。
- **自动出手要先解锁**：没在修行树上点「**生根**」之前，角色**不会自动攻击**，只能靠点击。「生根」的价值因此是"省手"，不是"打得更多"。
  - 这一段在战斗区中央靠上飘一个**气泡**「点击鼠标攻击敌人」，**每隔几秒轻微果冻缩放一次**——静止的提示看两眼就过滤掉了，定时的轻微弹动才读得成"重要信息"。解锁自动攻击后气泡自行消失。
- **过渡期的数值口径**：修行节点投固定值不投百分比；**双方都没有"防御力"**。
- **战斗公式的权威口径在 [combat.md](combat.md)**（`DMG1 / DMG2 / DMG3`、事件顺序、出手快照、频率分离）。
  一句话形状：**打怪与打玩家是同一条管线**——`最终伤害 = DMG1 × 通用增伤 × 暴击 × BD增伤 × 易伤`，
  只是目标不同。玩家的减伤只有**闪避与护盾**两条，且都落在承伤方（闪避是"承伤方减伤"，
  不是"攻方命中 vs 守方闪避"的对抗体系）。没有任何防御、抗性、格挡、招架、穿甲。
- 5 个境界，每个境界关联 3 个技能；需先解锁境界，再解锁与强化技能。
- **开局不附带任何法术**，玩家只有普攻；第一个法术要自己在技能页花灵钱习得。数值刻度（标准怪 = 1 SU = 3.5 下普攻）与关卡倍率的推导口径见 [balance_ttk.md](balance_ttk.md)，`level.csv` 的倍率列由 `tools/BalanceCurve` 生成。
- 15 个技能解锁后全部自动释放，独立冷却；没有合法目标时不空放。**例外是神通**：配置了触发概率的法术不自动释放，改为在普攻出手时按概率触发。**全名单只剩一个神通**——御雷真诀（10%，期望周期 15 秒，"中彩票"的那一发）；焚天剑诀与寒冰龙卷曾经也是神通，实测"整个妖王层不可控、成长反馈不明显"后改回了固定冷却。
- **功能性技能（控场 / 减速 / 增益）的触发概率要有上限**——高频触发会把"控制"变成"常驻"，与「攻速不加速增益类法术」是同一类护栏。
- 角色在地上或未来御剑术飞行时，都能被攻击，不判断跳跃或空地可攻击性。
- 画面上方显示角色 HP 条。
- 怪物具有攻击距离，支持近战、远程、法术攻击；进入攻击距离后停下攻击。
- 怪物允许重叠，不用实体阻挡形成排队。
- 怪物分**地面与空中**两层；技能声明自己能打哪一层（打地面 / 打空中 / 都能打），**飞行单位免疫只打地面的技能**。定位与层的配对规则见 [monsters.md](monsters.md) 与 [../data/fields.md](../data/fields.md)。

## 已确认：养成

- 修行：从左向右发展，只显示已加点及相邻节点；纵向最多 5 行，横向可扩展。提供属性、技能、功能解锁及功能强化。
  - **根节点直接分三支，每支职责单一**：
    | 支 | 走向 | 终点 |
    | --- | --- | --- |
    | **生存**（最上行） | 单线向右，全是生存属性 | 破土（与输出线汇合） |
    | **掉落**（中间行） | 掉落 +1 → **开启自动攻击** | 自动攻击（该支就此为止） |
    | **输出**（最下行） | 第二列分成两支：**剑气**（近战变远程）与 **攻击力**；法术 / 铸造 / 参悟沿攻击力那条线一字排开 | 同为破土 |
  - **只用两种货币，每个节点单一消耗**：**关键节点用灵核**（1 级、1 个：自动攻击 / 剑气 / 法术 / 铸造 / 参悟），**养成节点用灵石**（可配多级）。
  - **灵核节点就是章节门**（用户定的规划口径）：灵核全游戏只由 BOSS 首杀产出，所以"点得出下一个灵核节点"天然等价于"打得过下一只 BOSS"。
    **两个灵核节点之间的那一段灵石节点，就是那一关（那一段）的数值投放预算**——想控住某一段的强度，就把下一个灵核节点摆到那儿。第 1 关的预算因此是"根 → 拔节"与"生存 → 生存2 → 生存3"这两小段。
  - **灵核节点尽量放高价值功能**（系统解锁、掉落率、技能概率这类），**少放纯加伤害 / 加气血的属性**——那些交给普通节点去稀释，免得一眼就被看出"这一格最值钱"。
  - **过渡期一律投固定值**（`atk_flat` / `hp_flat`），不投百分比。理由是要让"再来一下能不能打死"能一眼算出来；百分比那条路径保留着，后期要投再投。
  - **开局只有一个节点**（根节点「+1 攻击」，3 级上限）；点它才延展出两条分支，之后汇到「生根」。
  - 树上的**解锁类节点**（激活自动攻击 / 剑气 / 境界）是**开关不是档位**，所以都是 1 级——写成多级的话"点第二级"什么都不会发生。

## 已确认：系统逐步解锁

- **开局五大系统全部锁着**，靠游戏进程一个个打开——放置游戏的前期代入感来自"从无到有"，而不是一上来摊开五套成品系统。
- **首次击杀普通怪**解锁「修行」；**裂隙不算怪**（它是一道门，不移动不攻击），不触发。
- 「**法术 / 铸造 / 参悟**」都放在**修行树**上，各是一个 1 级节点、各花 1 颗灵核，都挂在「生根」底下（见下）。
  解锁是**推导**出来的（`Systems.ByEffect`：效果 → 系统），不在买节点时另写一份状态——
  读档与改配置都不可能让两边对不上。加载期强制"每个 `*_system` 效果都登记过"，漏一个就是**永久锁死且不报错**。
- 页签**始终可见但置灰**，点进去是一张说明页（写清为什么锁着、怎么解开），**不隐藏**——"还有东西没开"本身就是盼头。
- **锁的样子**（三件套，缺一样都读不出"这里锁着"）：页签**右上角一把小锁**、操作区上一层**压暗遮罩 + 中间一把大锁**（并**拦住点击**），点进去的那张说明页在遮罩下面。
- **解锁的那一刻要炸开**：页签上的小锁与操作区的遮罩各碎一次（白光核 + 扩散的环 + 八块四散的碎片，与怪物死亡同一套读法）。锁若只是"下一帧就不见了"，玩家不会注意到刚才发生了什么。
- **首次解锁会强制切到那一页，并"先罩住、再碎开"**（约 0.45 秒）：解锁多半发生在**别的页面**上（在星图点出「法术」、在战斗里杀掉第一只怪），不切过去玩家根本不会注意到多了个功能；而直接切过去、内容瞬间铺满，又容易被当成"我刚才点到哪了"。所以先切页 → 真内容铺好 → 遮罩与大锁压在上面**并拦住点击** → 到点碎开露出内容。
- 解锁状态存在 `PlayerState.UnlockedSystems`，取值只允许 `Systems.All` 白名单；**旧档缺这个字段时，有进度的补成全部解锁**（那些存档本来就走过教学了，让它们回头锁一遍是平白罚人），新档保持全锁。
- 铸造：打造、穿戴、强化、洗练，只有一个武器装备位。
- 参悟：获得 4 类货币；4 个强化子页面用于强化 15 个法术。
- 剑灵：独立悬浮作战单位，可以抽取，最多同时装备 3 个；每个可装备 3 种不同的增强 Buff。
- 技能详细设计、修行节点与规则、铸造细节后续补充，不自行视为已定方案。

## 已确认：参悟与收取

- 参悟采用类似挖矿的点击交互，后续解锁自动参悟。
- 参悟页面打开期间，战斗继续。
- 离开参悟页面后，在线自动参悟继续，未收取产物保留。
- 产物可以合并数量，积存上限可以配置。
- 鼠标移到产物上即可收取，不要求按住鼠标。
- 退出游戏不继续生产。

## 框架确认状态

刷怪激活与推进、死亡统一回关卡起点、灵核首杀定量投放均已确认，当前没有需要再次确认的框架阻塞项。技能、天赋、铸造等内容细节按后续系统设计补充。

## 实现建议（尚未确认为规则）

- 角色使用独立的推进停止距离；各技能射程独立，远射程技能不必改变角色停步位置。
- 刷怪点使用稳定 ID 和世界横坐标，格号用于区域划分及 UI；“越过刷怪点”只关闭该点后续刷新，不删除已生成怪物。
- BOSS 首杀与关卡首通分开记录；首杀标记、累计投放和背包奖励在同一次存档提交中保存。
- 复活读条期间冻结战斗与刷怪计时，避免等待期间堆怪；在线参悟照常继续。
- 未收取参悟产物随存档保留，容量满时停止继续生产，不自动兑换入背包。
- 退出/重进时战斗恢复粒度、Buff 与技能冷却恢复方式另行明确；不计算退出期间收益。
