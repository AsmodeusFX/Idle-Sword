# 战斗底层规则：DMG1 / DMG2 / DMG3

> 状态：**已确认规则**。本文是战斗公式与结算顺序的权威口径。
> 刻度与关卡曲线归 [balance_ttk.md](balance_ttk.md)；属性边界与 `DamageModifier` 归 [fightattr.md](fightattr.md)；
> CSV 列与字段说明归 [../data/fields.md](../data/fields.md)。**四处冲突时以各自领域的这一份为准**，不要各写一半。
>
> 本文由 `docs/battle/` 下那两份外部规范（《战斗公式》《属性规范》V1.0）**改写并入**而成（2026-10-07）。
> 并入时没有照抄：那两份是一套通用 ARPG 框架，与本工程既有的 SU 刻度、修行星图、关卡曲线、
> 地面/空中分层、波次刷怪都没有对齐，而且**漏掉了玩家承伤这一整条路**。凡与工程现状不同的地方，
> 本文按工程现状写，并把差异记在「与那份外部规范的差异」一节。

## 0. 一句话版本

| 层 | 回答的问题 | 唯一实现 |
| --- | --- | --- |
| 面板属性 | 我现在有多强？ | `GameSession.Attack` / `MaxHp` / `AttackSpeed` / `SkillCdr` |
| **DMG1** | 这一发**本来**能打多少？ | `DamageFormula.Dmg1` |
| **DMG2** | 这一发**发生了什么**？ | `GameSession` 的事件顺序（本文第 3 节） |
| **DMG3** | 这一笔**最终**被放大多少？ | `DamageFormula.Final` |

```
最终伤害 = DMG1 × Generic × Critical × Build × Vulnerability
```

`DamageFormula` 是**纯函数、只此一份**，三个消费者共用：逐拍模拟（`Features/Battle/GameSession`）、
期望模型（`Core/Data/LevelCurve`）、自检（`tests/`）。为什么"只此一份"不是口号：
模型与模拟是同一条公式的两种算路（一个解期望、一个逐次结算），抄第二份的后果是两边**静默分叉**——
工具给的建议值和实际打出来的不一样，而两边都不报错。这条纪律在本工程已经栽过一次（见 `LevelCurve` 顶部注释）。

## 1. 不实现的清单（首版）

以下系统**都不存在**，也不要因为"以后可能需要"就提前写进结算：

`DEF` / 护甲 / 魔抗 / 减伤 / 元素抗性 / 格挡 / 招架 / 穿甲 / 抗性穿透。

双方都没有防御力。攻击者一侧承担**输出成长**（攻击力 × 技能倍率 × 暴击 × 通用增伤 × BD 增伤），
敌人一侧承担**耐久成长**（HP + 关卡倍率）。唯一的目标侧缩放是**易伤**。

命中/闪避的**对抗体系**也不建立：怪物没有命中属性，玩家也没有可破的敌方闪避。
玩家身上那 2% 的 `dodge` 是**承伤方减伤**，不是"攻方命中 vs 守方闪避"（见第 5 节）。

> ⚠️ **术语撞名**：`SwordSkill.pierce_chance`、`trajectory = line_pierce`、`CombatEffect.Pierce` 说的是
> **弹丸穿透**（一支剑穿过一整排敌人），与上面禁掉的"穿甲"毫无关系。看到 `pierce` 别当成穿透防御。

## 2. DMG1：原始伤害

```
DMG1 = AttackPower × SkillRate + SkillFlat
```

**`AttackPower`** 是最终面板攻击力，构成写死在一处（`GameSession.Attack`）：

```
攻击力 = (atk_base + 武器攻击) × (1 + atk_percent + 天赋百分比) + 天赋平攻
武器攻击 = Equip.base_atk × (1 + 0.15 × 淬炼等级) × 洗练系数
```

- **武器在乘区之内**（它与 `atk_base` 同类，都是"基础攻击"）。
- **天赋平攻在乘区之外**：它是"开局先从 +1 起步"那种固定值，并进乘区会被武器与百分比放大成
  完全不同的量级——那不是这个节点想表达的东西。

**`SkillRate`** 是技能**自身的永久成长**：

```
SkillRate = SwordSkill.power × (1 + skill_level_bonus × (技能等级 − 1) + 参悟 damage_percent)
```

- 普攻的 `SkillRate` 就是 `fightattr.basic_power`（当前 1.0）。
- 参悟（`damage_percent`）落在这里而不是 DMG3 的通用增伤池，因为它**是针对某一式剑诀的**培养，
  属于技能定义的一部分。放进通用池会让"这一式练到几层"和"全伤害 +20%"混成同一个数，
  之后再也区分不出"是技能强还是 BD 强"。
- **条件性放大不属于这里**。同一式在"目标残血""目标带状态""某个 BD 成立"时打得更疼，
  那是 DMG3 的 Build 乘区。分界只有一条：**技能定义 vs 这一发遇到的条件**。

**`SkillFlat`**（`SwordSkill.csv` 的 `skill_flat` 列，当前全表 0 = 尚未投放）：

> ⚠️ **它是给"固定伤害类"招式留的位置，用之前先想清楚**。攻击力在这款游戏里是随境界与修行
> 呈量级成长的（第 1 关 10 → 第 100 关 51 + 修行满配），而 `skill_flat` 是个**不随境界缩放的数**。
> 配一个 20 上去，在第 1 关是"多发半刀"，到第 50 关就是 0.0001%——它会静默失效，而没有任何东西会报错。
> 只在"这一式的伤害本来就该与攻击力无关"时用它（例如按目标最大气血结算）。

## 3. DMG2：战斗事件瀑布

DMG2 不是"一个倍率"，而是**一次攻击发生之后依次发生了什么**。顺序是口径的一部分，改动它等于改规则：

```
① Attack Event        出手：判定这一发属于谁、什么技能、打哪一层
                      —— 全游戏唯一的暴击判定点（逐弹丸/逐段各摇一次）
② Target Resolution   选出合法目标：活着、层对得上（`hits` vs `monster.layer`）、在射程/落点内
③ Hit Resolution      目标合法性复核 → 未通过则**不结算**（不是"未命中"，见下）
④ Damage Event        构造一笔 DamageEvent（快照 + 目标当下状态）
⑤ DMG3                算最终伤害
⑥ Apply Damage        扣 HP + 记账（`GameSession.ApplyDamage`，唯一入口）
⑦ OnDamage/OnHit/OnCrit   吸血、击退、聚怪、施加状态（`Hit` 的尾段）
⑧ Death → OnKill      掉落、首杀、裂隙击破（`ApplyDamage` 的尾段）
⑨ Chain / Trigger     **尚未实现**（见第 8 节）
```

不是每次攻击都走完⑨：没锁到目标就停在②，层不匹配就停在③。

### 3.1 层（地面 / 空中）是**目标合法性**，不是命中率

怪物分地面与空中两层（`monster.layer`），技能声明自己打哪一层（`SwordSkill.hits`，空 = both）。
**飞行单位免疫只打地面的技能**。

它是"这一发本来就够不着这一层"，不是"这一发没打中"：
- 没有摇骰子；
- 不产生任何"闪避/未命中"的表现；
- **不在伤害统计里留下一次命中**（`damage <= 0` 不进账，见第 7 节）。

选敌那一层（`Pick`/`Picks`/`Target`）已经不锁非法层的目标；`Hit` 开头那道复核是**最后一道防线**，
专门拦 `aoe_all`（全场扫描）之类绕过选敌的路径。

### 3.2 暴击：判定在 DMG2，倍率在 DMG3

- **判定**（"这一发是不是暴击"）：一次 **Attack Event 摇一次**，写进 `CombatEffect.Critical`。
  多段技能每支弹丸/每段各摇一次，所以"第 1 段暴击、第 2 段不暴击"是正常的。
- **倍率**（"暴击后是多少倍"）：`fightattr.crit_damage`（默认 1.5），进 DMG3 的第二乘区。非暴击恒为 1。
- 暴击率合计 = `crit_rate` + 临时加成（醉仙望月步），按 `fightattr` 的 `max_value` 夹取。
- 暴击率与暴击伤害**必须能各自调**，所以两件事不许混在一个数里。

### 3.3 多目标：一次出手 → 多个 DamageEvent

一次 Attack Event 命中 N 个目标（贯穿 `line_pierce`、全体 `aoe_all`、多弹丸、地面场的每跳）
时派发 **N 个 DamageEvent**：

- **共享**出手快照（暴击结果、暴击倍率、共享倍率窗）；
- **各自**结算目标侧修正（易伤、斩杀、利用状态），因为那些要读**这一只**当下的状态；
- **各自**记账（`DamageStats` 因此能看出"这一发打到了几只"）。

### 3.4 出手快照（本文最重要的一条）

一次 Attack Event 在**产生的那一刻**快照攻击者侧的一切：

| 快照项 | 落在哪 |
| --- | --- |
| `AttackPower` × `SkillRate` + `SkillFlat`（即 DMG1） | `CombatEffect.Damage` |
| 暴击结果 | `CombatEffect.Critical` |
| 暴击倍率 | `CombatEffect.CritDamage` |
| 共享伤害倍率窗 | `CombatEffect.BuffPower` |

由这一发**派生**的一切结算都**共享这份快照、不重新摇**：同一弹丸的其余命中、地面场每跳、
天降落点、**灼烧每跳**、召唤物射击。

为什么这么定：
- **期望值不变**。逐跳重摇的期望与一次摇定共享完全相同（线性期望），但一次摇定让"一次出手"
  在账目与观感上对得上；
- 反过来（逐跳重摇）的话，同一条火海会一跳暴击一跳不暴击——玩家看到的是同一个技能在随机翻倍；
- 灼烧的每秒伤害因此**在施放那一刻定格**（`EnemyState.DotDps`），此后只有目标侧修正会变。

> **例外只有一处**：召唤物射击用 `Launch(..., inherits: effect)` 继承**召唤那一手**的快照。
> 注意它的准确含义是"**不重新摇**"，而不是"不算暴击"——召唤那一手才是 Attack Event，
> 射击是它派生的结算。配置上它体现为 `Launch` 的 `attackerSnapshot: false`。

**目标侧修正不吃快照**：易伤按目标**落地那一刻**的状态算，所以弹丸飞到一半目标才中的易伤照样吃到。

### 3.5 灼烧（DOT）走的是"只叠目标侧"的入口

`TickEnemies` 里灼烧每跳调 `HurtEnemy`（而不是 `Hit`），因为攻击者侧已经冻进 `DotDps` 了——
再走一遍 `Hit` 会把暴击与倍率窗**算第二遍**。`HurtEnemy` 的语义因此是明确的：
"传进来的数已经是攻击者侧结算完的量，本函数只叠目标侧修正"。

## 4. DMG3：最终伤害

```
DMG3 = GenericMultiplier × CriticalMultiplier × BuildMultiplier × VulnerabilityMultiplier
```

| 乘区 | 池的性质 | 取值 | 来源 |
| --- | --- | --- | --- |
| Generic | **加算**：`1 + Σ` | `fightattr.generic_damage`（当前 0，尚无投放） | 面板属性 |
| Critical | 独立 | 非暴击 1；暴击 `crit_damage` | 面板属性 + DMG2 的判定 |
| Build | **乘算**：`Π` | 共享倍率窗 × 斩杀 × 利用状态 | 攻击者侧、带条件 |
| Vulnerability | **乘算**：`Π` | 目标当下的 `VulnerableFactor` | 目标侧 |

**为什么通用增伤加算、BD 增伤乘算**：前者是基础成长区，加算才压得住数值膨胀（三个 +50% 是 ×2.5
而不是 ×3.375）；后者是组合区，乘算才有"多个组件咬合起来明显变强"的**成型感**。

**Build 乘区目前有三个来源**，全都是"条件成立才生效"的倍率：

| 来源 | 条件 | 值 | 载体 |
| --- | --- | --- | --- |
| 共享伤害倍率窗 | 增益生效中 | `power != 1` 的增益类法术的威力 | `CombatEffect.BuffPower` |
| 斩杀 | 目标气血比例 < 阈值 | ×2 | `SwordSkill.secondary = execute` |
| 利用状态 | 目标带着任意状态（减速/寒冷/眩晕/灼烧/易伤） | ×(1 + `secondary_value`) | `SwordSkill.secondary = bonus_vs_state` |

**判断标准**：只要一个效果是"角色**长期拥有**、各养成系统能直接投放的静态属性"，它进 `fightattr.csv`；
只要它是"**满足某个条件才**对某一笔伤害生效的倍率"，它进 Build/Vulnerability。
把 `boss_damage` / `low_hp_damage` / `fifth_hit_damage` 这类东西一列一列加进属性表，
就是这条边界的典型反面教材。完整判断流程见 [fightattr.md](fightattr.md)。

### 4.1 `atk_percent` 与 `generic_damage` 在数值上是同一个乘区

`(1 + atk_percent)` 与 `(1 + generic_damage)` 乘在 DMG1 的同一个位置上，**数值等价**
（只有 `SkillFlat ≠ 0` 时才分叉，而当前全表为 0）。两条同时存在只为**展示口径**：

- `atk_percent` 是**面板攻击力成长**：玩家在攻击力那一行看得见它变高；
- `generic_damage` 是**伤害成长**：它不上面板攻击力，只在打出去的伤害上体现。

> ⚠️ **同一个养成来源只能选一边投**。两边都投等于给同一个效果乘两次，而面板上只会显示一半，
> 玩家永远算不清。取舍：想让玩家"看到攻击力涨"就用 `atk_percent`；想表达"伤害本身提高"（将来还要
> 按伤害类型分池：技能伤害 / 普攻伤害）就用 `generic_damage`。

## 5. 频率与伤害分离

`AttackSpeed` 与 `CDR` **不是伤害属性**，一律不进任何乘区。
混在一起的话 DPS 会随攻速平方增长，而玩家在面板上永远算不清自己为什么变强了。

| 属性 | 作用 | 形式 |
| --- | --- | --- |
| `fightattr.attack_speed` | 只改**普攻**频率 | `普攻间隔 = basic_interval ÷ (1 + attack_speed)` |
| `fightattr.skill_cdr` | 只改**法术**频率 | `冷却 = cooldown ÷ (1 + skill_cdr)` |

- 两者都**用除法**，所以再大也不会出现零冷却——这就是 CDR 需要的全部护栏。
  上下限写在 `fightattr.csv` 的 `min_value` / `max_value` 列上（`attack_speed` 上限 3、`skill_cdr` 上限 1），
  夹的是**合计值**（基础 + 各来源），所以增益也吃同一条上限。
- **增益类法术两样都不吃**。否则仙风云体术（15s 冷却 / 6s 持续）会在持续期内转好，等于自己给自己减冷却，
  变成 100% 常驻；两个 15s 增益还会互相锁死。
- 剑灵（`PetSkill`）与神通（`trigger_chance > 0`）算**法术**那一档，吃 `skill_cdr`。
- **加速类增益（仙风云体术）同时给两样**。它的文案就是"出手快如疾风"，而 `LevelCurve` 那条期望曲线
  是按"普攻与法术一起加速"推的——只给一边会让曲线整体变形，而 `--check` 只会告诉你曲线变了、不会告诉你为什么。

> ⚠️ **另有一条按秒数缩减的路**：醉仙望月步暴击后缩短一个随机技能的冷却（`secondary_extra`，当前 1 秒）。
> 它不走 `÷(1+cdr)`，所以**可以**把冷却扣到很低。约束是**它必须小于能砸到的最短冷却**——
> 当前最短是御剑术的 1.2 秒。以后调这两个数（缩短秒数 / 各技能冷却）时要一起看。

**期望 DPS**（模型侧，`LevelCurve.Dps`）：

```
DPS = 攻击力 × [(普攻每秒倍率 × 普攻频率 + 技能链 × 法术频率) × 暴击期望 + 技能链 × 影分身]
暴击期望 = 1 + 暴击率 × (crit_damage − 1)
```

## 6. 玩家承伤走**同一条管线**

怪物打玩家也是一次 Attack Event（`攻击力 × 1.0 + 0`，怪物的攻击力在刷怪时已经乘过关卡倍率与波次系数）。
玩家只是**另一个目标**，同一条 `DamageFormula`：

| 环节 | 玩家这一侧是什么 |
| --- | --- |
| Target / Hit Resolution | `dodge`（闪避）——**承伤方减伤**，不是命中/闪避对抗 |
| DMG3 的四个乘区 | **当前全中性**（怪物不会暴击，玩家也不吃易伤） |
| Apply Damage | 先扣护盾、再扣气血 |

顺序**不能改**：无敌（GM 开关）→ 复活读条短路 / 闪避 → 护盾 → 扣血。
闪避排在护盾**之前**，所以躲开的那一下**不消耗护盾**。

玩家侧乘区表留空是为了"以后给玩家加一个受创乘区"时不必再开第二条路——不是"玩家这侧永远没有乘区"。

## 7. 记账契约（`DamageStats`）

伤害统计挂在 `ApplyDamage`（**全游戏唯一给敌人造成伤害的地方**），口径与面板列一一对应：

- **有效** = 实际打掉的血（`before − after`）；
- **溢出** = 名义伤害里超出剩余血量的部分（`伤害 − 有效`）；
- **命中** = 落血次数，`伤害 <= 0` 不进账（苍穹剑陨落地那个 `Damage = 0` 的爆炸余韵因此不会凭空多一次命中）；
- **记账必须在易伤乘区之后**：在 `Hit` 里读 DMG1 会漏掉目标侧那一档，数字会偏小。

归因来源：法术/剑灵技能用 id，**普攻用空串**，影分身那一份归到**复制它的法术**（剑二十三）名下
（分身装的是什么值要能单独看出来，不能藏在被复制的那一式里）。

## 8. 链式事件：只定了结构与边界

工程**没有**事件总线、没有 `OnHit`/`OnCrit`/`OnKill` 钩子、没有 Modifier 注册表。
现有的"触发"是三个写死的机制（神通概率触发、影分身复制、暴击缩冷却），它们**不是**这套结构的实现。

将来要做链式事件（攻击 → 暴击 → 额外飞剑 → 击杀 → 爆炸 → 新的伤害）时，规则先定在这里：

1. **额外攻击必须产生新的 Attack Event**（`Launch`），不许直接改原 Damage 的数值；
2. 每个事件携带 **Source / Depth / TriggerHistory**；
3. **深度上限 = 8**。到顶就停止派发新事件，不许无限接力；
4. **同一事件不得再次触发自身**（A→B→A 要能识别出来）；
5. 事件只能**产生新事件**或**施加状态**，**不许绕过 `ApplyDamage` 直接改最终伤害**。

`DamageModifier`（`Core/Data/DamageFormula.cs`）与 `ModifierZone` 就是为这件事先摆好的落点：
`Generic` 加算池、`Build` / `Vulnerability` 乘算池的**列表形态求值**已经在
`DamageFormula.BuildMultiplier` / `VulnerabilityMultiplier` 里，接上注册表时直接用。

## 9. 验收口径（自检里的可执行形式）

| 用例 | 自检 |
| --- | --- |
| DMG1 / DMG3 的加算与乘算、最终公式、文档算例 858 | `DMG1 / DMG3：加算池与乘算池的区别，以及最终公式` |
| 攻速只改频率、不改单次伤害 | `攻速只改普攻频率，不改单次伤害` |
| CDR 只改频率、不改单次伤害 | `CDR 只改法术频率，不改单次伤害` |
| 上下限夹的是合计值（增益也吃上限） | `属性的上下限是硬护栏：增益把合计顶过 max_value 就夹回上限` |
| 玩家承伤走同一管线，闪避在护盾之前 | `玩家承伤走同一条管线，且闪避排在护盾之前` |
| 层是目标合法性，不结算也不记账 | `层不匹配是目标合法性失败，不是一次『未命中』——既不结算也不记账` |
| 出手快照：灼烧继承施放时的暴击 | `出手快照：灼烧的每秒伤害在施放那一刻定格，继承那一发的暴击` |
| 召唤物射击继承召唤那一手的快照 | `召唤物射击继承召唤那一手的快照，不重新摇暴击` |
| 曲线模型与属性表对账（锚点校验活着） | `曲线模型与 fightattr 对账：改了主轴常量而不同步锚点，模型会响亮失败` |
| 多段各自摇暴击、多目标各自结算目标侧 | `伤害分级：多目标形态确实按波次人数结算`、`暴击相关` 若干条（既有） |

既有且**必须保持绿**的锚点：`SU 锚点：裸开局 3 刀打死标准怪`、前期 TTK 链、易伤的 `850` 与 `150`、
`利用状态` 的 `1.3`、`影分身继承 70%`。

## 10. 加新机制时的落位流程

1. 它是**角色长期拥有、可被各系统直接投放**的静态属性吗？→ 是则进 `fightattr.csv`（`docs/design/fightattr.md` 的四步判断）。
2. 它决定"**多久一次**"吗？→ 频率轴，进 `attack_speed` / `skill_cdr`，**不许**进任何伤害乘区。
3. 它决定"**这一发本来能打多少**"吗？→ DMG1：动 `AttackPower`、`SkillRate` 或 `SkillFlat`。
4. 它决定"**这一发发生了什么**"吗？→ DMG2：事件顺序、目标合法性、暴击判定、派发新的 Attack Event。
5. 它是"**满足某个条件才对这一笔生效的倍率**"吗？→ DMG3 的 Build / Vulnerability（生成 `DamageModifier`）。
6. 都不是？→ 多半不该进战斗系统，先回 `docs/design/value_inventory.md` 看它属于哪一类价值。

## 11. 与那份外部规范的差异（并入时逐条对账）

| 外部规范怎么写 | 本工程怎么做 | 为什么 |
| --- | --- | --- |
| `SkillFlat` 作为 DMG1 的常规一项 | 只留列、全表 0，并写明"不随境界缩放"的陷阱 | 攻击力是量级成长，固定值会静默失效 |
| `attack_speed` 管普攻、`CDR` 管技能 | 一致（本轮从"一个 haste 通吃"改成两条轴） | 语义干净；同时给 CDR 补上了上限规则 |
| 通篇只有攻击者一侧的公式 | **补上玩家承伤**：同一条管线、玩家只是另一个目标 | 工程有近战/远程怪，玩家本来就挨打 |
| `Hit Resolution` 里提命中/闪避，又说首版不建立 | 明确写成：**层 = 目标合法性**、`dodge` = 承伤方减伤，都不是命中率 | 工程已有"飞行免疫地面技能"这条硬规则 |
| `Attack Event` 只有一个 Target Resolution | 明确多目标 = 一次出手派发多个 DamageEvent | 工程有贯穿 / 全体 / 多弹丸 / 地面场每跳 |
| 没提出手快照 | 写成正式规则（DMG2 的核心之一） | 工程本来就是逐弹丸摇一次暴击，只是没写下来 |
| 没提多段/派生结算的归因 | 记账契约写死（含影分身归到剑二十三名下） | 面板要能回答"这个技能到底值多少" |
| 不说境界台阶 | 不碰；台阶取 ×1.7（见 `doc_audit.md` C1） | `balance_ttk.md` §6 的 K=4 已作废 |
| 提到 "Penetration" 要禁 | 明确 `pierce` 是**弹丸穿透**，与穿甲无关 | 否则照抄会把在役机制误删 |

## 12. 已知的待办与不一致（写下来，别当成没有）

1. **影分身那一项不吃加速**。期望模型里 `DPS` 的影分身项**不乘任何频率乘区**，而 `LevelCurve` 里
   它上面的注释却写着"攻速与暴击作用于全链"——**注释与公式互相矛盾**。本轮**逐字保留**了公式
   （改动它会让全 100 关的 `normal_hp` 变一遍，实测第 100 关 +4.9%），因为那属于"要不要修这个模型"
   的独立决定。要修的话走 `balance_ttk.md` §8.2 的步骤并整条重算曲线，别顺手改。
2. **`level.csv` 与模型本来就有 394 处偏差**（`--check` 红），与本轮无关，见 `balance_ttk.md` 顶部。
3. **按秒缩减冷却**与 `÷(1+cdr)` 是两条路，前者没有统一护栏（见第 5 节的告警）。
4. 链式事件、`OnHit`/`OnCrit`/`OnKill` 钩子、Modifier 注册表**都还没实现**（第 8 节只定了边界）。
5. `DamageType` 枚举已定义但**没有消费者**——它是为"按伤害类型分池的通用增伤"预留的标签位。
