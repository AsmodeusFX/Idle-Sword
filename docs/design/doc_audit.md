### 2. 改前的 1.638 偏差结清了 —— 归到"模型的命中密度常数"，不是夹具

旧夹具是"5 只清一色**地面**青苔妖、`1e8` 无敌血、无预热、只记 `Effective`"。换掉之后
**10 关 0.99 / 30 关 1.19 / 60 关 2.80**。前两关进带，60 关那 2.80 **不是夹具问题**：

`LevelCurve.HitsPerCast` 的 `PerBlade = 1.2` / `PerTick = 2` 是**与场上敌人数无关的定值**，
而实测里"一次出手打一片、且持续打"的形态（`skill_02` / `skill_12` / `skill_06` / `skill_18`）
命中数**随密度增长**（`skill_02` 在第 60 关实测 547.7 命中/次 vs 模型 18.5）。
单发类与直线类全部对得上（`skill_01` / `skill_07` / `skill_11` 实测 ÷ 模型 = 1.00 / 1.00 / 0.97）。

**结论**：正确做法是把密度常数改成**场上目标数的函数**，而它要先等 Phase 1 的期望参悟练度。
**本轮不动** —— 结论与实测表记在 [DPS评估与战斗模拟系统方案.md](../temp/DPS评估与战斗模拟系统方案.md) 附二。

### 3. 计划里猜错的一条

嫌疑名单第一条「起手齐射把比值抬高了」**方向是反的**：第 30 关 60 秒窗下冷启动 **1456**、预热后 **1618**。
预热期真正的用处是**吸收走进射程那段斜坡**（靶子铺到 1440，玩家在 `LevelStartX = 80`）。
`ProbeRequest.WarmupSeconds` 的注释与收敛断言按实测方向写。

### 4. 三条纪律是从 `GameSession.Step` 的顺序里逼出来的（都不是设计选择）

- `Effective + Overkill` 才是标称伤害（只记 `Effective` 会静默扣掉每次过量击杀，而模型侧 `Dps` 是输出上限）。
- 出手计数**不能**抄 `UI/Audio.cs` 的「冷却 0 → 正」——冷却衰减是 `Math.Max(0, cd − dt×factor)`，
  而 `CastSkills` 在**同一个 `Step`** 后半段就把冷却写回正值，从 `Step` 之后观察那个 0 永远看不到
  （实测第 30 关只认出一式）。改用"冷却涨上去"。也**不能**比 `Effects` 集合差（增益类走 `CastBuff`，不产生 `CombatEffect`）。
- `FieldSupply` 供给策略必须**显式**：`Hold` / `WaveCadence` / `Single` 在同一关给出 0.99 / 0.223 / 0.021 —— 不写清楚就是静默分叉。
