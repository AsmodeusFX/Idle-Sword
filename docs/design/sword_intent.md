# 剑意系统设计（逐技能拓展方案）

> 状态：**设计稿（已拍板方向，未填数值）**。本文定"每个技能能往哪些方向长"，**不填具体 `value`**；数值与产能留到实现那一轮。
>
> 本轮改了三件**地基**（见第十节）：`SkillBonus` 按 `effect` 分类、存档不再拒绝超过等级上限的等级。
> 关联：[sword_skills.md](sword_skills.md)（15 剑诀设计）、[balance_ttk.md](balance_ttk.md)（刻度与成长口径）、[skill_values.md](skill_values.md)（数值水位）、[../data/fields.md](../data/fields.md)（字段字典）。

## 一、现状盘点

| 部分 | 现状 | 性质 |
| --- | --- | --- |
| 参悟产出 | `contemplation.csv` 4 块灵石 → 4 类剑意货币 | **可用**，但间隔 3/4/5/6 秒的差异尚无设计含义 |
| 剑意货币 | `item.csv` 的 `intent_0..3`：风 / 雷 / 霜 / 炎之剑意 | **可用** |
| 剑意强化 | `SwordUpgrade.csv` **60 行 = 4 档 × 15 剑诀** | **这就是"每个技能可拓展的范围"的物理位置**，一个技能四格 |
| 效果 | 56 行 `damage_percent`（`value 0.08`）、剑二十三那 4 行 `inherit_percent`（`0.01`） | **占位样例** |
| 结算 | `SkillBonus(skill, effect)` —— **按 effect 分类**求和（本轮刚拆开，此前不分 effect） | **可用** |

当前伤害公式：

```
技能伤害 = 最终攻击 × skill.power × (1 + 0.15×(剑诀等级−1) + SkillBonus(id, "damage_percent"))
影分身继承比例 = secondary_value + 0.01×(等级−1) + SkillBonus(id, "inherit_percent")   # 不封顶
```

**只有三条路吃等级 / 剑意**：威力、增益类冷却、影分身继承比例。其余十几个正交旋钮（弹数、穿透概率、触发概率、半径、次级强度、时长…）**目前全部硬读 CSV**——这是实现那一轮的主要工作量（见第五节）。

## 二、三条口径（已定）

1. **剑意是"质变"，不是数值档。** 数值档（伤害 / 半径 / 时长 / 次级强度）只作**每格兜底**，优先做**改变行为**的那类。
2. **四格按技能单独设计，不按元素套公式。** 元素名只是货币归属（风/雷/霜/炎四页签），**不承担**"风=数量、雷=触发"这类硬映射——每个技能的四个格子按它自己的身份来设计。
3. **成长不封顶。** 每条剑意的 `value × 等级` 线性、无上限（与技能等级同一条口径）。**唯一例外是概率类**（触发概率 / 穿透概率）天然封顶 100%——这类格子的文案要写清"满了之后不再成长"。

> 顺带一条**护栏**：`effect` 白名单里只放**已经有消费点的**取值（[GameConfig.cs](../../idle-sword/Core/Data/GameConfig.cs) 加载期校验）。不要"先放开白名单、实现留到以后"——那会留下"配置上写了、战斗里没人读"的**静默失效**，而拦住静默失效正是这个项目一直在做的事。

## 四、实现优先级

按"**一档机制能覆盖几个技能**"排——先做覆盖面广的，最后做单技能专属的。

| 档 | 机制 | 为什么排这里 | 覆盖 |
| --- | --- | --- | --- |
| **T0** | **把现有配置列接到剑意上**：弹数 / 穿透概率 / 触发概率 / 冷却 / 半径 / 时长 / 次级强度 | **零新机制**——这些值战斗里已经在读了，缺的只是"剑意能改它"这条通路。**所有 ✗ 的兜底格都在这一档** | 15 个技能全覆盖 |
| **T1** | **状态联动**：对携带状态增伤 / 按状态数增伤 | 一条乘区吃下 4 个技能，而且补上维度矩阵里唯一完全空白的那一列（见 [skill_review.md](skill_review.md) §三） | 焚天剑诀 / 斩鬼神 / 御雷真诀 / 寒冰龙卷 |
| **T2** | **击杀触发**：返还冷却 / 连锁 / 蔓延 | 需要一个"击杀钩子"，但一处实现能被多条剑意复用 | 青元剑芒 / 天剑 / 焚天剑诀 / 剑气流云壁 / 斩鬼神 |
| **T3** | **专属机制**：概率免费释放（延迟施法）/ 留场"剑墙" / 多分身 / 叠爆 / 破盾爆炸 / 多龙卷 | 每个只服务一个技能，成本最高——**但最"有意思"** | 御剑术 / 剑气流云壁 / 剑二十三 / 苍穹剑陨 / 剑罡护体 / 寒冰龙卷 |

> **实现前提**：`Progression.SkillBonus` 必须**按 `effect` 分类查询**（本轮已拆）。此前它不看 effect、凡 `skill_id` 命中就全求和，任何新 effect 一走它就会**串味到伤害里**。
> **一个工程建议**（来自 [skill_review.md](skill_review.md) §五）：注入点很分散（弹数 / 穿透 / 触发概率 / 次级强度 / 范围 / 冷却分布在 4~5 处），每加一条 effect 就要打一圈补丁。**值得把"该技能在当前等级与剑意下的实际参数"收口成一个 `EffectiveSkill` 结构**，`Launch` 一路只消费它。T0 那一档正好是把这件事一次做对的机会。

## 五、协同设计：技能等级不封顶

**目标**：技能升级给的那个数值**线性、无天花板**，这样玩家后期用别的手段把等级顶过 `max_level` 时，公式照常给收益。

**现状核对**：

- `SkillPower = power × (1 + 15% × (等级−1) + 剑意)` —— **线性、没有夹取** ✓ 这条已经是"上不封顶"。
- `max_level`（剑诀 50 / 剑意 20）在**战斗计算里一次都没被读** ✓ —— 它只是**购买闸门**（`SwordRealmSystem` / `SwordIntentSystem`）+ 界面档位。
- **已经修掉的一处真 bug**：`SaveStore` 原先是 `rank > max_level → 抛异常拒绝整份存档`，也就是"玩家突破等级上限"这件事会**读档即崩**。现在只校验"是个合理的非负整数"，上限归购买闸门。

**还要设计的两处"枯竭"**：

| # | 问题 | 补法 |
| --- | --- | --- |
| 1 | **增益类的成长会到顶**：`BuffCooldown` 的下限是 `持续 × 1.25`（覆盖率封顶 80%），大约**等级 25 之后每级什么都不给** | 冷却触底后，**每级转成该增益自己的强度轴**——仙云 → 攻速比例、醉仙 → 暴击率 / 暴击缩短秒数、剑罡护体 → 护盾量、剑二十三 → 继承比例。这样**每条增益都有一个永不枯竭的轴**；与"炼气档不该给满"不冲突（那是**峰值**，只在冷却触底后才开始涨） |
| 2 | **概率类剑意天然封顶 100%**（触发概率 / 穿透概率） | 文案写清"满了则不再成长"；或（记待办）满后转成"连发 / 弹数"这类不封顶的轴 |

## 六、产出与消耗（测算，数值待定）

单条剑意点满（`cost = 8`、`max_level = 20`，成本 `cost × (级数+1)`）：`8 × (1+2+…+20) = 1,680` 份。

| 范围 | 需要份数 |
| --- | --- |
| 单个剑诀 × 单种剑意 | 1,680 |
| 单页（15 剑诀） | 25,200 |
| 全部 4 页（60 条） | **100,800** |

产能（`contemplation.csv`，满仓 200）：

| 剑意 | 自动间隔 | 单页 25,200 所需 |
| --- | --- | --- |
| 风 `intent_0` | 3s | 21.0 小时 |
| 雷 `intent_1` | 4s | 28.0 小时 |
| 霜 `intent_2` | 5s | 35.0 小时 |
| 炎 `intent_3` | 6s | 42.0 小时 |

全部点满约需 **126 小时纯在线**（不含手动点击，且自动参悟需先解锁天赋）。**两个待解问题**：

1. **「每 10~20 分钟必须收一次」与放置定位冲突**（`capacity = 200` 使积存在 10~20 分钟内到顶并暂停计时，而本作不做离线产出）。要么提高 `capacity` 把收取周期拉到 1~2 小时，要么加"满仓后按较低速率继续累积"。
2. **产能差异（3/4/5/6 秒）目前没有设计含义**。建议把它变成定价依据：**产出越慢的剑意单级效果越强**，让"投哪一系"成为真实取舍。

## 七、界面与交互

- 保留 4 个页签 + 每页 15 个剑诀按钮的结构（与 `core_rules.md` 一致）。
- 每个按钮显示：名称、当前等级/上限、**该行实际效果**（按 `effect` 渲染，如「剑支 +0.2/级」而不是统一的「效果 +8%」）、下一级消耗。
- 页签上给一行该系的定位说明，让四个页签的分工一眼可见。
- **未习得的剑诀应禁用其强化按钮**并提示「需先习得此剑诀」——现在 `UpgradeIntent` 不检查这一条，可以先强化一个还没学的技能，投入被浪费。
